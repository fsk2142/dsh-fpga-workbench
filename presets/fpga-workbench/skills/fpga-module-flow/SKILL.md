# FPGA 模块开发流程

> ⚠️ **本篇是早期的雏形,留着当对照,不要照它建目录。**
> 它里头的产物路径(`<缓存目录>/<模块名>/lint/`、`/sim/`、`/synth/`)是拍出来的、没跟用户确认过;
> 现在改用模块根下的阶段文件夹:`spec/ lint/ sim/ comp/ synth/ timing/ review/`(见 `fpga-spec` 的约定文件)。
> 出口判据那部分会分别搬进各阶段技能,搬完这一篇就可以删。

**工具在哪、怎么调:看会话开头那段「本机 FPGA 工具链」。** 路径由用户在「设置 → FPGA 开发模式」里填、由宿主核对过存在性。不要用 `where`/PATH 另找一份,也不要假设某个工具一定可用 —— 那段文字里标了「未就绪」的环节就跳过,并在结论里点名。

## 四段,每段都有可判定的出口

1. **Lint(秒级)** —— Verilator `--lint-only -Wall`。
   出口:`-Wall` 下零 warning;每一条压制掉的 warning 都要写清理由(例如厂商原语没有仿真模型)。**有 warning 不算通过。**
2. **功能仿真(ModelSim)** —— 命令行 `-c` 模式跑测试平台。
   出口:测试平台自己报 PASS/FAIL,而不是你读波形后得出的印象。失败用例的日志要留下。
3. **综合与时序(Vivado batch)** —— `-mode batch -source <脚本.tcl>`。
   出口:综合无 error,且时序报告里 WNS ≥ 0;不满足的路径要写明是哪条、为什么暂时接受。
4. **证据归档** —— 前三段的日志与报告落到缓存目录,并留下能复现的命令。

跳过任何一段都必须在结论里点名,不能默默跳过。

## 产物放哪

只写缓存目录(路径见提示段),不要污染 RTL 源码目录:

```
<缓存目录>/<模块名>/lint/     verilator 输出
<缓存目录>/<模块名>/sim/      vsim 日志、波形、覆盖率
<缓存目录>/<模块名>/synth/    vivado 日志、journal、时序报告
<缓存目录>/<模块名>/run.log   这一轮做了什么、命令原文、结论
```

## 说"完成"之前

- 结论要能指到具体位置:`<文件>:<行>`,或日志里的某一行。不要只说"仿真通过"。
- 没跑过的检查写成**未验证**,不要写成"应该没问题"。
- 长任务(综合、大回归)放后台任务跑,读日志判断,不要前台死等;开跑前先说清预期耗时。
- 动 RTL 对外接口、约束文件、或工作区之外的东西之前先问,不要顺手改。
