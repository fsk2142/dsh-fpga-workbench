# project-integrate:顶层集成

## 前置(这条是硬门槛)

**要集成的那些模块,模块级流程必须跑完并通过确认。** 具体是:

- 该模块的 `lint/`、`sim/`(有比对就含 `comp/`)都有结论,而且不是 FAIL
- 有审查结论就一并看(`review/`);没有审查至少要有各阶段的 PASS

没跑完就集成 = 把没验过的东西塞进整机,后面出问题时你分不清是模块的错还是接线的错。
**状态不清就停下来问用户**,不要"先接上看看"。

> 不是每个模块都会进工程 —— 只做交付物的模块(给别人用的 IP)跑完模块级就算完成。
> 这里只管**工程 spec 的模块清单表里列出的**那些。

## 干什么

1. **选顶层**:工程顶层(`*_top`)在哪,把模块实例化进去
2. **时钟与复位**:每个模块用哪个时钟、复位的来源与极性、跨时钟域在顶层怎么处理
3. **接口对接**:位宽、符号、协议、握手方向 —— 逐条对,不要"看着差不多"
4. **加进工程**:源文件加进 Vivado 工程的 srcs;IP 加到工程里(按器件选对应目录)
5. **连得上**:跑一次 elaborate 或综合,确认没有未连接端口、没有多驱动、位宽不匹配

## 判据

- **PASS**:elaborate/综合能过;顶层没有未连接或悬空端口;跨时钟域的地方在顶层有明确处理
- **FAIL**:位宽/符号对不上、多驱动、少连时钟复位、跨域没处理
- **BLOCKED**:某个模块还没跑完模块级流程(= 前置不成立)
- **NOT_APPLICABLE**:这次没有要集成的模块(纯顶层改动)

## 产物

写 `<工作区根>/project/integrate/integrate.md`:

- 结论 + 每个模块的实例名(顶层文件里的例化名)
- **接线表**,一行一个接口:

  | 模块 | 实例名 | 时钟 | 复位 | 接口 → 对端 |
  |---|---|---|---|---|

- 跨时钟域的地方:哪两个域、怎么处理的
- 跑过的命令原文 + 日志路径(能复现)
- 没接完或临时悬空的地方:**明确写出来**,不要留个 TODO 就不提

## 常见坑(按踩到的频率排)

- 位宽与符号:接了但少一位、或补错符号位 —— elaborate 不报错,仿真空欢喜一场
- 时钟域:两个模块看着都跑同一个时钟,实际一个是分频出来的
- 复位:一个模块高有效、一个低有效,顶层直接接过去
- 例化名与文件名不一致,后面找信号找到怀疑人生
