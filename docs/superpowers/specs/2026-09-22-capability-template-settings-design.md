# FPGA 能力工具与模板库设置设计

日期：2026-09-22

## 目标

把当前按开发阶段重复配置工具路径的设置，改成“顶部登记本机工具，模块与工程只选择已就绪工具”的能力配置。模块和工程不是流水线；AI 可以按任务在 RTL、仿真、验证、综合与实现能力之间反复切换。

同时引入按固定目录分类的模板库。同一种模板只维护一个目录，模块和工程可以各自选择不同文件；模板只是可编辑起点，不会自动串联或自动执行开发阶段。

本轮只修改插件设置、内置模板、相关说明和测试，不修改 `presets/fpga-workbench/skills/**`。

## 顶层界面

设置页保留三个顶层区：

1. 工具设置
2. 模块工具
3. 工程工具

“工具设置”整体默认收起，标题旁显示“已就绪数量 / 总数量”，右侧提供“展开设置 / 收起”。展开后包含：

- 脚本工具、编译工具、仿真工具、FPGA 工具四组工具卡。
- 语言与库映射。
- 模板库路径。

每个本机工具仍独立展开、检测和保存。路径保存后收起，卡片显示“已就绪”；工具检测失败必须显示为检测失败，不能显示成“没有检测到”。

原“开发约定与模板”整块删除。语言、标准和 ModelSim 库映射放入“语言与库映射”；六个全局模板路径不再作为可见设置。

## 能力卡，而不是阶段流水线

模块工具包含四张卡：

| 能力卡 | 可选工具角色 | 模板槽位 |
| --- | --- | --- |
| RTL 编译工具 | compiler | RTL 模板 |
| 仿真测试工具 | simulator | Testbench 模板、仿真编译脚本、仿真运行脚本 |
| 脚本验证工具 | script | 验证脚本模板 |
| 综合与门禁工具 | fpga | 综合脚本、约束模板 |

工程工具包含三张卡：

| 能力卡 | 可选工具角色 | 模板槽位 |
| --- | --- | --- |
| 工程主工具 | fpga | RTL 模板、约束模板、综合脚本、实现脚本、下载脚本 |
| 系统仿真工具 | simulator | Testbench 模板、仿真运行脚本 |
| 脚本验证工具 | script | 验证脚本模板 |

工程规格讨论不显示工具卡，规格能力和技能本身不在本轮删除或修改。

每张能力卡默认收起，收起态必须显示：

- 当前工具：由 AI 判断、明确不用、具体工具名，或具体工具失效警告。
- 每个模板槽位：使用内置默认模板、已选择的模板名，或已选择模板失效警告。

展开后才显示选择器和保存按钮。工具选项包含：

- 由 AI 从已就绪工具中判断。
- 角色匹配的工具；已就绪项可选，未就绪项可见但禁用并说明原因。
- 明确不用。

能力卡不提供任何路径输入框。每张能力卡独立保存；关闭时未保存草稿不得写入正式设置。

## 设置数据模型

设置模型版本升级为 `3`，所有字段继续使用字符串，以适配当前宿主 schema。

能力工具字段：

- `moduleRtlTool`
- `moduleSimulationTool`
- `moduleVerificationTool`
- `moduleGateTool`
- `projectMainTool`
- `projectSimulationTool`
- `projectVerificationTool`

每项默认 `auto`，也可保存具体工具 key 或 `none`。

模板库根字段为 `templateLibraryPath`。模板选择分别保存在各能力卡的模板槽位中；模块和工程不共用选择值。空字符串表示“使用与所选工具匹配的内置默认模板”。内置选择使用 `builtin:<相对路径>`，用户库选择使用 `library:<相对路径>`；旧版绝对模板路径可原样保留为兼容选择。

旧版阶段字段和六个全局模板路径继续以隐藏字段进入 schema，至少保留一个兼容周期，不参与新模型的日常解析，也不在迁移时清空。

## 工具就绪与解析

工具就绪的唯一来源是顶部工具登记：路径非空、存在且文件或目录类型正确。能力卡不得再次检测工具，不得保存第二份路径。

显式选择的工具后来失效时，保留选择并显示警告；不得自动改成其他工具或 `auto`。`auto` 表示 AI 在执行具体任务时从已登记且就绪的工具中判断，不表示自动排程或自动执行。

## 模板库

内置库和用户库采用同一固定分类：

```text
templates/ 或用户选择的 FPGA-Templates/
├─ rtl/
├─ constraints/
├─ verification/
├─ simulation/
│  ├─ testbench/
│  ├─ compile/
│  └─ run/
├─ synthesis/
├─ implementation/
└─ programming/
```

不增加 `fpga/` 中间层。

扫描规则：

- 初次打开设置页、刷新状态和收起卡片时均不扫描模板目录。
- 每次展开一张能力卡，只扫描该卡使用的分类；关闭再展开会重新扫描。
- 分类目录内部允许厂商子目录，递归扫描普通文件；不跟随符号链接或目录联接，不跨出分类根。
- 忽略隐藏文件和常见临时文件，单分类最多返回 500 项，超限必须标记。
- 内置模板与用户库模板同时显示，并标明来源和相对路径。
- 用户库不存在、不可读或部分分类不存在时，内置模板仍可显示，同时明确提示用户库问题。
- 扫描、选择和解析全部只读，不复制、移动、改名或删除用户文件。

已保存模板的存在性可以用精确路径 `stat` 判断，这不是目录扫描。模板文件后来消失时，保留原选择并显示警告，不得静默退回内置模板。用户主动把选择留空时才使用内置默认模板。

内置模板可以声明适用工具。明确选择不兼容工具时，内置不兼容模板禁用；用户模板的兼容性未知，不做武断禁用。若所选工具没有适配的内置默认模板，空选择仍允许保存，但必须显示警告。

## 内置标准模板

新设置扫描以下分类模板：

```text
presets/fpga-workbench/templates/
├─ rtl/systemverilog_module.sv
├─ constraints/vivado_xdc.xdc
├─ verification/python_data_comp.py
├─ simulation/testbench/systemverilog_testbench.sv
├─ simulation/compile/modelsim_compile.do
├─ simulation/run/modelsim_run.do
├─ synthesis/vivado_synthesis.tcl
├─ implementation/vivado_implementation.tcl
└─ programming/vivado_program.tcl
```

ModelSim 编译脚本只负责编译；运行脚本只负责加载、运行和结果门禁。Vivado 综合、实现、下载脚本互不自动调用。脚本必须要求显式配置项目事实、失败时返回失败，不隐藏地组成流水线。

当前不内置 Quartus 完整工程模板，因为插件尚未承诺完整 Quartus 工程流程。选择 Quartus 而未选择用户模板时，界面应提示缺少适配默认模板。

为了不在“只改设置”阶段破坏现有技能和生成工具，原根目录六份模板暂时作为隐藏兼容资产保留，新模板扫描不包含根目录文件。下一轮修改技能时再统一旧引用。

## 旧设置迁移

迁移必须幂等，且不删除旧值。

- v1 全局工具设置可先转换成等价的内存中 v2 结果，再迁到 v3；最终只写一次 v3 补丁。
- 模块能力从最接近的旧阶段选择继承：RTL、验证仿真、验证脚本、综合。
- 工程系统仿真和脚本验证从旧系统仿真选择继承。
- 工程主工具从旧集成、约束、实现、时序、上板和发布的 FPGA 工具选择中求一致结论：非空显式选择一致时继承；冲突时改为 `auto` 并记录迁移警告；全为 `none` 时迁为 `none`。
- 旧阶段覆盖路径按具体工具归组。同一工具路径一致、且顶部登记为空时可迁入顶部登记；路径冲突或与现有顶部登记不同则不猜测，保留旧值并记录警告。
- 六个旧全局模板路径分别继承给对应的模块和工程模板槽位。即使文件已经不存在，也保留路径并显示失效警告。
- 原规格阶段的脚本工具选择不迁入任何新能力卡。

迁移警告保存在隐藏字符串字段中并通过状态接口显示，不包含用户路径全文，只点明需要确认的工具或能力。

## 宿主接口

现有状态接口继续返回字段、工具卡和预设同步状态，并改为返回 `capabilities` 能力卡元数据和解析状态；不再把旧阶段 `stages`/`bindings` 作为新客户端的布局来源。

新增只读模板接口：

```text
GET /plugins/fpga-workbench/templates?capability=<allowlisted-key>
```

接口只接受已登记能力 key，通过能力定义得到要扫描的分类。响应包含每个分类的内置项、用户库项、截断状态和错误。未知能力返回非 2xx 错误，不能扫描任意调用方提供的路径。

工具检测接口和模板接口的非 2xx、Malformed JSON 或异常必须在客户端显示为失败，不能折叠成空结果。

## 会话提示

会话提示继续强调“能力配置，不是执行顺序”。它列出：

- 本机已登记且路径有效的工具。
- 七张能力卡的工具选择和可用性。
- 各能力卡明确选择或默认解析到的模板路径；显式模板缺失时只警告，不回退。
- 模板库路径只作为来源说明，不触发目录扫描。

设置不会生成命令队列，不会自动调用综合、仿真、实现或下载。

## 验收标准

- 工具设置整体可展开和收起，工具仍独立检测、保存。
- 模块四卡、工程三卡准确显示，无规格工具卡、无阶段路径输入框。
- 未就绪工具可见但不可选，既有失效选择不被重写。
- 同类模板共用一个库目录，模块与工程选择互不覆盖。
- 只在展开能力卡时扫描对应分类，乱序请求不会覆盖较新的结果。
- 缺失模板、不可读库、HTTP 错误和 malformed response 都有不同于“没有模板”的失败提示。
- v1/v2 设置可迁移到 v3，冲突不猜测，旧值不删除。
- 分类内置模板都存在，ModelSim compile/run 以及 Vivado synth/implementation/programming 职责分离。
- 源码检查、宿主加载检查、已安装副本检查和本地安装冒烟通过；真实 DSH 客户端仍由用户重启后人工确认。
