# 时序判据细节

## I/O 延迟:按端口类型决定要不要清零

`no_input_delay` / `no_output_delay` 的判据**不是「必须为 0」**,而是
**「标了『必须有』的端口,不能在缺延迟的名单里」**。

| 端口类型 | I/O 约束 | 为什么 |
|---|---|---|
| SDRAM / DDR / SRAM 接口 | **必须有** | 数据与时钟有明确建立保持窗口,不约束就不分析 |
| 以太网 / USB / PCIe 等高速串行 | **必须有** | 收发时序是协议硬要求 |
| 与**外部同步器件**交换数据的并行总线 | **必须有** | 对方有自己的时钟,相位关系必须建模 |
| 视频接口(HDMI / LVDS / MIPI) | **必须有** | 像素时钟域跨到外部器件 |
| SPI / I2C 等**源同步**接口(本端出时钟) | **建议有** | 时钟由本端产生,但仍需建模输出延迟 |
| LED / 数码管 / 蜂鸣器 | 不需要 | 人眼看,毫秒级都无所谓 |
| 按键 / 拨码开关(已做消抖) | 不需要 | 输入已异步化,不靠时序窗口 |
| 纯内部逻辑,端口只连测试点 | 不需要 | 无外部时序关系 |

**怎么用**:拿到 `check_timing` 的数字后,先看**具体是哪几个端口**没延迟,
再对照这张表。报告正文里 `no_input_delay` 那节会列出端口名。

## 未约束路径的六类来源

对着这张表逐个排除,比盲查快得多:

| 来源 | 典型场景 | 约束方式 |
|---|---|---|
| 输入路径缺失 | 从输入端口到内部寄存器,端口没 `set_input_delay` | `set_input_delay` + `create_clock` |
| 输出路径缺失 | 从内部寄存器到输出端口,没 `set_output_delay` | `set_output_delay` |
| 衍生时钟 | 门控 / 分频产生的时钟没声明 | `create_generated_clock` |
| 异步复位 | 复位信号没做 `set_false_path` 或复位时序约束 | `set_false_path` 或 `set_max_delay` |
| 虚拟时钟 | 外部器件接口没建虚拟时钟模型 | `create_clock -name virt` |
| 纯组合路径 | 输入直通到输出的组合路径 | `set_max_delay` |

## `check_timing` 十二项:哪些代表「未约束」

| 项 | 含义 | 要它为 0 |
|---|---|---|
| `no_clock` | 有寄存器但没时钟 | ✅ |
| `unconstrained_internal_endpoints` | 内部端点没有任何时钟约束 | ✅ |
| `generated_clocks` | 衍生时钟没连到源 | ✅ |
| `no_input_delay` / `no_output_delay` | 端口没有输入/输出延迟 | 看端口类型(见上表) |
| `partial_input_delay` / `partial_output_delay` | 只约束了一部分 | 看端口类型 |
| `constant_clock` | 时钟被常量驱动 | ✅ |
| `pulse_width_clock` | 脉宽不足 | 看设计 |
| `multiple_clock` | 一个端点被多个时钟驱动 | 查是否真跨域 |
| `loops` | 组合环路 | ✅ 必须修 |
| `latch_loops` | 锁存器环路 | ✅ 必须修 |

## 为什么只报一个角不够

FPGA 的延迟随**工艺、温度、电压**变化,同一个设计在不同角落下的时序余量不同:

| 角 | 温度/电压 | 容易出什么问题 |
|---|---|---|
| **slow**(慢角) | 高温 / 低压 | **建立时间**违例(逻辑太慢,数据没按时到) |
| **fast**(快角) | 低温 / 高压 | **保持时间**违例(逻辑太快,数据跑过头) |
| typical | 常温 / 标称电压 | 参考值 |

**关键点:快角的问题单角跑不出来。** 如果只跑默认角(通常含 slow),保持时间违例
可能完全不报 —— 上板后表现为「偶发错位」「温度低时更容易错」。

判据:**每个角都 `WNS ≥ 0` 且 `WHS ≥ 0`**。只报一个角记 `UNVERIFIED`。
