# project-syssim:工程内仿真验证

**rtl 之后做这件事。** 目标很直接:**能测的模块尽量测**,用**厂商仿真器**验一遍。

- 测试文件与脚本、日志:**`sim/`**(根目录;不放 `src/` 下)
- 仿真器:**设置里选中的那个**(见会话开头「本机 FPGA 工具链」)—— 优先用厂商仿真器
  (Vivado XSim / ModelSim·QuestaSim 那条线),**不得另挑一个**
- 结论:**`doc/syssim.md`**

**spec 定下之后没有固定流程**:本技能与其它工程级技能都是**按需取用**,可并列、可回跳、可只做其中几样;见 `fpga-project-spec`。

## 前置

1. 相关 RTL 已平铺在 `src/rtl/`(见 `fpga-project-rtl`)
2. 根 `sim/` 下有工程级可跑的 `tb_*`;没有就先补工程级 tb,再回来跑。`src/sim/` 的简单 tb
   只作专用模块开发反馈,不能代替这里的工程证据
3. 仿真器在设置里已就绪;缺工具 → 如实记 `BLOCKED`,不要假装跑过

## 干什么

**仿真内部三级顺序**(就这件事本身):① 单模块 → ② 多模块联合 → ③ 整个工程。
一级没有明显问题再进下一级 —— 这是**仿真的内部顺序**,不是工程流水线,
也不要求「仿真全绿才许做别的」。

**与其它工程级技能无固定先后**(spec 之后皆按需)。综合/出 bit 前尽量 `rtl` / `sim` / `xdc` 完好
(软约束)。lint / synth 见另两个技能,本技能只管 sim。
**不要把跳转限制死**;综合之前尽量确保 `rtl` / `sim` / `xdc` 完好。lint / synth 见另两个技能,
本技能**只管 sim**。

### 1. 单模块仿真(先做完这个)

把根 `sim/` 里**当前跑得起来**的工程级 `tb_*` 按覆盖范围逐个跑:

- 能独立仿的先独立仿 —— 不必等顶层、不必等所有模块齐
- 每个 tb:**跑过一次**,看波形/日志确认没啥大问题(不握手卡死、不乱跳、主通路数据合理)
- 跑不了的(缺模型、缺库、缺激励)在 `doc/syssim.md` **列出来**,不要跳过不提

### 2. 多模块联合仿真

单模块都过了之后,把**相关模块**接起来仿(子系统/数据通路/接口对):

- 重点看接口:握手、背压、跨时钟、复位顺序、位宽/符号
- 激励优先用真实数据段
- 判「对不对」时拿独立参照比(见 `fpga-module-verif` 的口径);不要拿 DUT 输出当期望

### 3. 整个工程仿真

顶层/整机链路仿一遍(可与 `fpga-project-integrate` 的 elaborate 呼应):

- 从入口到出口的主通路、时钟复位释放、多模块一起跑时的稳定性
- **这一级没有明显问题**即可(不要求全绿才许做别的 —— 工程级无固定流程)
- 简单 tb 的结果**不算正式证据**;要进验收链须有独立判据(见 `fpga-module-verif`)

### 4. 跑法(厂商仿真器)

跑法用设置里选中的那个仿真器走。命令写进脚本,在 **`sim/`** 下一次调用,全程命令行;
调用姿势以会话开头的**已就绪**清单为准,不在本技能里重新探测工具:

- **ModelSim / QuestaSim**:先 `sim/compile.do`(`vlib` / `vlog`),再 `sim/run.do`(`vsim -c` / `run -all` / `quit -f`);两份脚本**按设置里选中的「仿真编译/运行」模板抄改**(路径见会话提示;工程级没有 `*-new` 起文件命令,不要对工程根跑 `module-verif-new`)。从工程 `sim/` 跑时把编译脚本 `RTL_DIR` 改成 `{../src/rtl}`(模块布局是 `{../rtl}`);编译与运行**两步**都带上设置里的 ini(`$env:MODELSIM_INI` 或 `INI_OVERRIDE`)。`quit` 与成败 gate 写进 `.do`
- **Vivado XSim**:`xvlog` / `xelab` / `xsim` 三步;**不要跑 `.do`**(那是 ModelSim 方言)

看波形用**已经确认过的那份脚本**起 GUI;不要在 `sim/` 里裸开 GUI 加载设计(dump 会被清零)。

## 判据

- **PASS**:该测的测过、无明显问题(或问题已定位说明);跑不了的列明原因 ——
  不要求「三级全绿」,按当时任务需要的覆盖面说清楚即可
- **FAIL**:有 tb 跑挂、数据明显不对、握手卡死、断言触发
- **BLOCKED**:仿真器没就绪 / 关键 tb 或激励缺失且补不了
- **UNVERIFIED**:只做了部分级别、或 tb 在但没跑完
- **NOT_APPLICABLE**:这次没有可仿的逻辑(纯粘合且用户认可不仿)

判定词含义见 `fpga-module-verif` 的**状态表**(唯一权威)。简单 tb 过了 ≠ 验证 `PASS`;
要写进验收链的结论,须有独立判据(见 `fpga-module-verif`)。

## 出问题往哪跳

| 现象 | 优先去 |
|---|---|
| 接口对不上、位宽/时钟接错、连不上 | `fpga-project-integrate` |
| 功能/逻辑不对、波形里算法走歪 | `fpga-project-rtl` |
| 激励、比对、tb 自己的问题 | 本技能(改 `sim/` 再跑) |
| 管脚/IO 电平/时钟约束 | `fpga-project-constraints` |
| 机械规范 / 编译器 lint | `fpga-project-lint` |
| 综合失败 | `fpga-project-synth` |

`rtl` / `sim` / `lint` / `synth` / `constraints` 与集成是**并列**的,不要求固定先后。

## 产物

写 `<用户指定工程目录>/doc/syssim.md`:

- 结论(`PASS` / `FAIL` / `BLOCKED` / `UNVERIFIED` / `NOT_APPLICABLE`)
- **测了哪些**:`sim/tb_*` 清单 + 各自命令/结果摘要
- **没测哪些**及原因(缺什么、为什么跑不动)
- 联仿:覆盖的跨模块路径、激励来源、比对方式与结果
- 日志/波形路径;新文件同步 `doc/files.md`

## 不要做的事

- 不要用**第三方/另一套**仿真器替代设置里选中的厂商仿真器
- 不要把模块级库里的完整验证报告当成工程内仿真结果 —— 工程内以 `sim/` 实跑为准
- 不要只跑一个 tb 就写 `PASS` 却不提其它能测没测的
