# project-syssim:系统级仿真

## 前置

1. 工程骨架在(`.fpga-workbench.json` 的 `kind` 为 `project`),见 `fpga-project-spec`
2. 顶层已集成、能 elaborate(`project/integrate/`)—— 连不起来就还没到联仿这一步
3. 各模块自己的验证有结论(`<模块根>/verif/verif.md`);结论缺的如实标出来,别在这里替它下结论
4. 激励数据与对照数据有来源(工程里已有的数据文件,或 spec 里定的生成方式)

## 做与不做的判断

**按风险判断,不按模块个数**。值得做的信号:模块之间有握手或背压、跨时钟域的数据流、接口协议
容易出错、或者上板代价高(要拆机、要外设)。单个模块自己就能测清楚、集成只是把单向数据连起来
—— 那就记 `NOT_APPLICABLE`,不得为了走流程造一个没用的顶层测试平台。

**判断随时可以改**:一开始没打算做,后来发现接口复杂了就补上,比一直不做强 —— 改判断时同步
更新 `project/spec/spec.md` 里那一行,免得文档与事实脱节。

## 和模块级验证的区别

模块级(`fpga-module-verif`)验的是"这个模块对不对";这里验的是"**互联之后是否仍然正确**" ——
重点在接口:握手会不会卡、背压会不会丢、跨时钟域的数据会不会错位、复位释放顺序对不对。

**模块级的测试平台不得当作顶层测试平台使用**,它们的检查目标不一样。

## 怎么做

1. 顶层测试平台放在 `project/syssim/` 下,**照测试平台模板写**(模板路径见会话开头那段)
2. 激励:优先用**真实的一段数据**(工程里已有的数据文件),比随机数更能暴露问题
3. 检查:数据比对 + 握手断言 —— 判"数据对不对"照模块级那套走(`fpga-module-verif`):
   拿独立参照比,比对脚本直接**复用模块级的参考模型**,不要另写一套(独立模型写两遍必然分叉)

## 本环节要跑的命令

跑法与模块级同一条路(见 `fpga-module-verif` 第二步)—— 命令写进脚本,一次调用,全程命令行,
在 `project/syssim/` 下跑(脚本、库与日志都落在那里)。

**跑法用设置里选中的那个仿真器**:是哪个、路径是什么、调用姿势(命令名与参数)是什么,会话开头
「本机 FPGA 工具链」的**已就绪**清单里都写着,**不得另行挑选一个**;选 XSim 时那条路径是 Vivado
的 `bin` 目录(不是可执行文件),照清单给的那个姿势跑。

需要脚本文件时,方言跟着选中的工具走 —— 这是脚本格式的差别,不是两种做法:

- **ModelSim / Questa** 用 `.do`:`vlib` / `vlog -sv` / `vsim -c -voptargs="+acc=rn"` /
  `run -all` / `quit -f` 那一套写进 `project/syssim/run.do`(自带 `templates/run.do` 就是一份
  `.do`,照它起一份、把源码集合与顶层换成工程的),再按已就绪清单里那条 `-c -do` 的姿势一次调用。
- **Vivado XSim** 用 `xvlog` / `xelab` / `xsim` 三步(或 `xelab` 出来的 snapshot),
  **不要跑 `.do`** —— 那是 ModelSim 的方言。

要人工看波形时,用**已经确认过的那份脚本**起 GUI —— ModelSim 是 `project/syssim/run.do`,
选 XSim 就是 `xelab` 出来的那个 snapshot:库映射、源码集合与顶层都由它决定。**不要在 `syssim/`
里直接开 GUI 加载设计** —— TB 在时刻 0 会以写方式打开它的 dump 文件,光是加载设计就会把那几个
文件清零。

## 判据

- **PASS**:顶层测试平台跑完,数据比对**取值逐个等价**、没有握手卡死与超时
  (双方只是写法不同、取值等价不算错 —— 与模块级同一条口径,见 `fpga-module-verif`)
- **FAIL**:取值不一致、或握手卡死、或断言触发
- **BLOCKED**:缺数据文件 / 缺顶层测试平台 / 仿真工具没就绪
- **NOT_APPLICABLE**:按上面那条判断,这个工程不做系统级仿真

## 产物

写 `<工作区根>/project/syssim/syssim.md`:

- 结论(`PASS` / `FAIL` / `BLOCKED` / `UNVERIFIED` / `NOT_APPLICABLE`)
- 命令原文 + 激励数据来源 + 比对方式与结果
- 覆盖了哪些跨模块路径、哪些**没覆盖**

系统仿真失败时,先排查接口(位宽/握手/时钟域),而非某个模块的内部逻辑 ——
模块级已经各自验过了。
