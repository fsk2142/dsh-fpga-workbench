# project-integrate:顶层集成

目录树、模块来源、从库拷什么、专用模块简单 sim 标准,都以 `fpga-project-spec` 为准,这里只写**接进顶层**这件事。

- 顶层:**`src/rtl/`**;模块 RTL:**`src/rtl/`**(见 `fpga-project-spec` 目录树)
- IP(`.xci` 等):**`ip/`**
- 工程:**`prj/`** (Vivado 建在这里;报告不进 `prj/`)
- 结论:**`doc/integrate.md`**

其余工程技能按需并列或回跳,见 `fpga-project-spec`。

## 前置

**三条基础要求**(早期集成与正式验收都要):

1. `doc/spec.md` 的固定小节齐:器件 part、工程名、**顶层模块名**、时钟目标、复位约定
2. `prj/` 下有 Vivado 工程;没有就按 spec 的器件 part 建到 `prj/`(工程名用 spec 里那个)。
   **不得**在别处建好再把整个工程目录拷进 `prj/`
3. 加进工程的源一律 **external reference**(引用 `src/` `ip/` `xdc/` 里那份),
   **不得再复制一份**：否则改了 `src/rtl/` 工程还在用旧副本

### 两种集成的差别

| 阶段 | 什么时候做 | 要求 |
|---|---|---|
| **早期集成** | 随时。搭顶层骨架、试接接口、跑一次 elaborate 看连不连得上、定位集成问题 | **唯一要求是把未验证的模块标出来**:接线表里写清来源列 + 风险/未验证说明 |
| **正式集成验收** | 往交付方向走的那一步 | 额外要求可复用模块的模块级结论齐(见下) |

**为什么早期要标注**:未验证的模块接进去,后续出问题时分不清是模块的错还是接线的错。

**正式验收额外要求**:

- **可复用模块**:模块级 `rtl/`、`verif/` 结论**都是 `PASS`**,或是有依据的 `NOT_APPLICABLE`。
  结论在**模块库**那套 `spec/rtl/verif` 里看,不在本工程目录
- **专用模块**:`src/rtl/` 有代码,`src/sim/` 里有 `tb_*` 且跑过一次(不进正式证据链)
- **顶层**不要求 `sim/` 自测

**`BLOCKED` / `UNVERIFIED` 不等于"有结论"**:遇到状态存疑(比如 `BLOCKED` 理由是「工具没就绪」)
先核实那条理由是否成立;不成立时按实测重新记,不得拿站不住的 `BLOCKED` 当通行证。

> 只管 `doc/spec.md` 模块清单表里列出的那些。可复用而库里没有的模块:**停止并报告**,
> 等人工按模块级流程写完再拷,不要在集成时自己另写一个顶上。

## 干什么

### 1. 选顶层

顶层模块名以 `doc/spec.md` 固定小节为准(不要另起名字)。顶层源文件放 `src/rtl/`,
把清单里的模块实例化进去。顶层自己的代码与各模块同级,不单独开目录。

### 2. 模块从哪来(按 `doc/spec.md` 清单表的「来源」列)

| 来源 | 怎么做 |
|---|---|
| 可复用,已拷入 | `src/rtl/`、`ip/`、`src/sim/` 里已有,直接用 |
| 可复用,待人工 | **停止该模块的集成**,报告用户;拷入后再接 |
| 专用,已有 | 使用 `src/rtl/` 已有源;缺失时转 `fpga-project-rtl` 补齐后再接 |

**从库拷什么、落到哪**:见 `fpga-project-spec` 的「模块来源与从库里取什么」,本环节用同一口径,
不重复。每拷一批记 `doc/files.md`(**工程里的位置 + 参考来源**)。

**文件名撞了就停下问用户**(两个来源都有 `pkg.sv` 这种)。不得静默改名、不得覆盖。

**不得**默默改模块接口去迁就顶层;接口对不上先回 `doc/spec.md` 改图/改约定。

### 3. 时钟与复位

每个模块用哪个时钟、复位来源与极性、跨时钟域在顶层怎么处理。
以 `doc/spec.md` 的**时钟目标 / 复位约定**固定小节为准;不一致先改 spec 再接线。

### 4. 接口对接

位宽、符号、协议、握手方向：逐条核对,不得以"大致相符"为由略过。对照
`doc/spec.md` 模块清单表的接口列 + `doc/flow.md` 框图。

### 5. 加进工程

- 源文件:`src/rtl/` 下用到的文件
- 约束:`xdc/` 下
- IP:`ip/` 下的 `.xci`

都加进 **`prj/`** 下那个 Vivado 工程的 srcs,且必须是**引用**(external / 相对工作区路径指向
`../src` `../ip` `../xdc` 那些真实文件),**工程内不得出现第二份拷贝**。不要往 `prj/` 里写报告
或手改 `.runs/`。

### 6. 连通性

跑一次 elaborate 或综合,确认没有未连接端口、没有多驱动、位宽不匹配。

**警告按归属分人改**(与 `fpga-project-rtl` 同一口径):

| 警告落在哪 | 归属 | 谁改 |
|---|---|---|
| 顶层 / 集成胶合逻辑 | 工程 | 本技能改 |
| `src/rtl/` 下本工程写的专用模块 | 工程 | 本技能或转 `fpga-project-rtl` |
| `src/rtl/` 下**从模块库拷入的** | **模块的问题** | **回模块库改**(`fpga-module-rtl`),改完重新拷入 |
| `ip/<ip-name>/` 下厂商 IP / 生成的 wrapper | 厂商或 IP 配置 | 改 IP 配置,不改生成文件 |

**集成阶段最容易把模块的问题「顺手改掉」**：那会让库与工程两份不一致。发现模块的问题,
**停下来报告并退回模块级**,不要在工程里就地改。

**还缺的专用 RTL 不在这里写**：集成只接已有源并核对接口;补写工程缺的 RTL 用
`fpga-project-rtl`。可复用而库里没有的模块依旧停止并报告,等人工模块级流程写完再拷。

**仿真发现问题时**:`rtl` / `sim` / `constraints` 与集成是**并列环节**,可任意顺序修复,
不必走完流程再回头(见 `fpga-project-syssim` 的「出问题往哪跳」)。

## 本环节要跑的命令

集成本身是编辑工作(改顶层、接接口),真正要跑的是**连通性检查**:

| 干什么 | 命令 |
|---|---|
| elaborate / 综合看连通性 | Vivado 批处理:`open_project prj/<工程>` → `launch_runs synth_1`(或 `synth_design -rtl` 只做 elaborate) |
| 机械规范(工程内 RTL,含顶层与专用模块) | `node "<自带命令目录>\project\project-rtl-check.mjs" <用户指定工程目录>` |
| 机械规范(可复用模块) | 在**模块库**里对那个模块跑:`module-rtl-check.mjs <模块根>` |
| 看波形(定位接口问题时) | 工程级用 `sim/` 里已确认的脚本(见 `fpga-project-syssim`);模块级用该模块**已经确认过的那份脚本**(见 `fpga-module-verif`) |

**注意命令层级**:`project-rtl-check.mjs` 接用户指定工程目录；`module-*` 命令只接模块库中
某个模块的根(其下有 `spec/rtl/verif/synth`),不要混用。

**早期集成**只跑 elaborate 就够(便宜、快);**正式验收**要求可复用模块的模块级结论齐(见「前置」)。

## 判据

- **PASS**:elaborate/综合能过;顶层没有未连接或悬空端口;跨时钟域在顶层有明确处理;
  源是**引用**不是第二份拷贝
 ：正式验收时还要求可复用模块的模块级结论齐(见上)
- **FAIL**:位宽/符号对不上、多驱动、少连时钟复位、跨域没处理
- **BLOCKED**:要正式验收,但某个可复用模块没有 PASS 结论,或该拷的库模块还没到位
- **UNVERIFIED**:骨架搭好了、还跑不了(模块未完成/工具没就绪)
- **NOT_APPLICABLE**:这次没有要集成的模块(纯顶层改动)

## 产物

写 `<用户指定工程目录>/doc/integrate.md`(**扁平固定名**,与其它工程级报告并列):

- 结论(`PASS` / `FAIL` / `BLOCKED` / `UNVERIFIED` / `NOT_APPLICABLE`)
  (判定词含义见 `fpga-module-verif` 的状态表)+ 每个模块的实例名
- **接线表**,一行一个接口:

  | 模块 | 实例名 | 时钟 | 复位 | 接口 → 对端 | 来源(库/专用) |
  |---|---|---|---|---|---|

- 跨时钟域:哪两个域、怎么处理的
- 跑过的命令原文 + 日志路径(能复现)
- 没接完或临时悬空的地方:**明确写出来**,不要留个 TODO 就不提
- 同步更新 `doc/files.md`(顶层与拷入文件:**位置 + 来源**)

## 常见坑(按踩到的频率排)

- 位宽与符号:接了但少一位、或补错符号位：elaborate 不报错,到仿真才暴露
- 时钟域:两个模块表面同一时钟,实际一个是分频出来的
- 复位:一个模块高有效、一个低有效,顶层直接接过去
- 例化名与文件名不一致,后续定位信号困难
- 从库只拷了 RTL、忘了 `.xci`,工程里 IP 是空的
- 工程里用的是**复制进来**的旧副本,`src/rtl/` 改了却不生效：必须用引用
