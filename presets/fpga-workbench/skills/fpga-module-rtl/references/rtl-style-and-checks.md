# RTL 规范清单

**总纲:一切格式以时序最优为先。** 下面各条是**格式约定**,与"时序更好"冲突时**格式让步**,
并在代码里写明理由。

**总纲优先于条文。** 后文出现的「禁止」「一律」「严禁」**默认允许时序例外** ——
例外时在代码注释里写一句为什么,不要因为怕违规而让时序变差。

例外只有两条不给让步,因为它们是**正确性问题**而非格式:
- 参考模型不得依据 RTL 编写(同源错误)
- 有效样本为 0 不得判 `PASS`

## 信号定义

### 类型

| 位置 | 类型 | 例 |
|---|---|---|
| 模块 **input** | `wire` | `input wire [7:0] din` |
| 模块 **output** | `logic` | `output logic [7:0] dout` |
| 模块 **inout** | `tri` | `inout tri sda` |
| **内部信号** | `logic` | `logic [7:0] din_d;` |
| 内部**唯一例外** | `wire`：**只**用于实例之间的连接网 | `wire [7:0] fifo_dout;` |

**函数 / 任务的形参不受上表限制**(那里的 `input logic x` 是变量)。
已有工程与外来代码的既有写法**不为统一而重排**。

### 位宽:避免大位宽信号

**能用窄的不用宽的,能拆的不要并成一条宽总线。**

大位宽的实际代价(不是风格问题):

| 代价 | 原因 |
|---|---|
| **布线拥塞** | 64 位信号跨区域要走 64 条线;局部拥塞时大幅降频 |
| **时序难收敛** | 位宽越大扇出越大;一条 128 位总线常成为关键路径 |
| **寄存器/LUT 占用翻倍** | 每打一拍就是 N 个 FF,多级打拍时 N 倍放大 |
| **功耗** | 宽度翻倍,翻转功耗约翻倍 |

做法:

- **只在需要的地方宽**：中间计算用够用的位宽,不按最大值一路传到底
- **能拆就拆**:128 位的"数据+标签"总线拆成 64 位数据 + 少量控制位,各自独立走
- **跨时钟域尤忌大位宽**:多比特跨域风险成倍(见 [跨时钟域与复位](cdc-and-reset.md))
- **避免整条总线打拍**:只对需要寄存的部分打拍,不为"求稳"把 256 位总路过一级触发器
- **按实际范围定位宽**:计数器按最大计数值定,不一律用 32 位

**例外**:协议强制的大位宽(AXI 数据通路、DDR 接口)照协议,拆不了。

### 字面量:每个都要带"宽度 + 基"

- **禁止 `'0`**(及同族 `'1` / `'x` / `'z`):宽度被藏起来,位宽一改就静默对不上。
  清零 / 置全用显式写法:`{N{1'b0}}`;数组、结构清零用 `'{default: 1'b0}`
- 其余写全 `N'基值`:**信号类**(控制 / 握手 / 状态标志)用 **`'b`**;数据类用 **`'h`**;
  `'d` 留给纯整数语境
- **例外**:`int unsigned` 的 `localparam`、循环变量、纯计数常量的十进制整数
  (`localparam int unsigned DEPTH = 16;`)

机械检查只查"带没带"宽度与基;「数据类 `'h` / 信号类 `'b`」靠读代码判,写进结论。

## 命名

**精准而简练**:一眼看出是什么：不堆修饰词,不靠后缀暗示组合还是寄存器。

| 用途 | 后缀 | 例 |
|---|---|---|
| 控制类信号的打拍 | `_r` | `tvalid_r`、`tlast_r`、`col_r` |
| 数据类信号的打拍 | `_d` | `crc_d`、`fill_len_d` |

**规则只有三条**:

1. **`_r` / `_d` 只给寄存器用**：组合信号不能加
2. **多级打拍**写 `_rr` / `_dd`,或并成数组形式;不为每级另造后缀
3. **没有语义就不加**：后缀只表达"这是打拍版"

**照常用的后缀**(名字本身有含义,不算自造):`_nxt`(次态/下一拍值)、`_sr`(移位)、
`_sum`、`_cnt`、`_en`、`_valid`、`_hold`、`_drv`(测试平台驱动量)。

**不用**:`_reg` / `_ff` / `_next` / `_n` / `_q1`(只为"看得出是寄存器")、`_c` / `_v`(对组合无信息量)、
`_q`(老式 Q 端写法)。

**主寄存器不带后缀**(`tot_len`、`state`)。**判定"是不是寄存器"看赋值不看后缀** ——
看 `always_ff` 里的 `<=` 左值或 `assign` 左值。

**同名孪生**:组合侧朴素名、寄存器侧加后缀(`ev_rx_pkt` / `ev_rx_pkt_r`)。
**端口名被冻结时**组合侧取有含义的名字(如 `tot_len_sum`)。

**已有工程与外来代码的既有命名不动**：不为统一格式去重排别人的代码。

**外来代码另行判断**:`rtl/ip/` 下的厂商 IP 与他人模块,机械检查**跳过**(不按本规范书写)。
这类代码的报错先与用户确认是否要改,**不得擅自重排厂商代码**。

## 排版

### 声明区:位置与分组

**位置**:先寄存器、后组合：`// ---- Registers (sequential state) ----` 在前,
`// ---- Combinational ----` 在后,两段各自按功能分组。

**分组**:每组一条注释,形制 `//--- 组名 ---`;**新增信号归到对应组**,不随手加在段末。
**端口同样按功能分组**(clock/reset 一组,其余按接口语义),形制与声明区一致。

**组合逻辑区按数据流顺序摆**:如 仲裁 → 源握手 → 输出接受与捕获 → 头部拼装 → 输出多路选择,
让人顺着数据流读下来。

### 注释

- **设计说明 1~2 行、至多 3 行**;**端口分组注释同样按 3 行办**：超出的细节移到块级注释
- **每个 `always` / `always_ff` / `always_comb` / `initial` 块有且仅有一条块首注释**,
  写清这个块在干什么;不写第二条、不让块首领错对象
- **三类例外**(不受 3 行限制):文件头、模块简介、断言里的 `Purpose :` / `Trigger :` / `Failure :` 块

## 写法

以下不是风格问题:写错会综合出与仿真不符的电路,或直接出 latch、出竞争。

### 时序逻辑用非阻塞 `<=`,组合用阻塞 `=`

```systemverilog
always_ff @(posedge clk) q <= d;      // ✅ 非阻塞
always_comb             y  = a & b;   // ✅ 阻塞
```

`always_ff` 里用阻塞 `=` 是最严重的一类错误:多个寄存器互相依赖时赋值顺序决定综合结果,
仿真与硬件执行顺序不同 → **仿真对、硬件错**。

**同一个块里混合两类必须拆开。**

### 组合块覆盖所有分支(防 latch)

组合块漏赋值 → 推出锁存器。latch 在 FPGA 里是非预期结构:无法时序分析、
`report_timing` 直接漏掉、跨域行为不确定。

```systemverilog
// 最省事:开头给默认值,分支覆盖它
always_comb begin
  y = 'h0;                 // ← 兜底
  if (sel) y = a;
end
```

**三个必写**:`if` 带 `else`、`case` 带 `default`、组合块开头给默认值。

**case 补充**:

- 状态机用 `unique case`:综合器检查未覆盖编码与多分支同时命中,比人工核对可靠
- `casex` 把 `x` 当 don't care,掩盖未知值传播 → **用 `casez` + 明确 `?`**

### 状态机必须有自恢复出口

```systemverilog
always_comb begin
  next_state = state;             // 默认保持,防 latch
  case (state)
    IDLE: if (start) next_state = RUN;
    RUN:  if (done)  next_state = IDLE;
    default: next_state = IDLE;   // 非法编码回 IDLE
  endcase
end
```

**非法状态能自恢复是硬要求**。上电时触发器状态不确定,无 `default` 的状态机会停在非法编码上,
表现是"上电就死"。

### 复位:默认同步高有效

**极性**:

- **默认高有效** `if (rst)`;不写 `rst_n` / `!rst` / `negedge rst`
- **AXI 按 AMBA 用低有效**(`ARESETn`);用户明确要求低有效时照办
- 已有工程原本低有效(非 AXI)则沿用

**同步 vs 异步**:

```systemverilog
// 同步复位(默认)
always_ff @(posedge clk) if (rst) q <= 'h0; else q <= d;

// 异步复位(仅少数场景)
always_ff @(posedge clk or posedge rst) if (rst) q <= 'h0; else q <= d;
```

**默认用同步复位**:FPGA 上更简单,BRAM/DSP 的复位行为本身要求同步。
异步复位只用于必须立即响应的场景(故障保护、上电强制初始态),且**必须同步释放** ——
见 [跨时钟域与复位](cdc-and-reset.md)。

**复位作用域(常被写错)**:

| 信号类型 | 要不要复位 |
|---|---|
| 控制信号、状态机、计数器、握手标志 | **要**复位 |
| **数据通路**(采样值、运算中间结果、流水线数据) | **通常不复位**：复位占用布线资源且无意义 |
| 移位寄存器、多级流水 | **不复位**(复位它等于浪费资源) |
| valid / 有效标志 | **要**(与数据配对) |

把整条 64 位数据通路都接上复位,是资源爆掉的常见原因。

### 时钟:三条禁忌

| 禁止 | 为什么 | 正确做法 |
|---|---|---|
| **门控时钟做使能**(`always @(posedge gated_clk)`) | 综合出 glitch-prone 时钟网络,时序无法分析 | 用 `enable` 信号:`always_ff @(posedge clk) if (en) q <= d;` |
| **组合逻辑产生时钟**(`assign clk2 = a & b`) | 同上,且跨域无法约束 | 用 `create_generated_clock` 声明衍生时钟;分频用 MMCM/PLL |
| **一个模块用多个主时钟** | 隐式多时钟域,必然有跨域信号 | 一个模块一个主时钟;多时钟必须显式声明并做同步 |

**另外**:不要在 `always` 块里给时钟赋值(`clk = ~clk` 只在 testbench 里用)。

### 位宽不匹配必须显式(高频真问题)

和「避免大位宽」是不同问题。这里指**跨位宽赋值/运算的隐式转换**。

```systemverilog
logic [7:0] a;
logic [3:0] b;
logic signed [7:0] s;

a = b;              // ❌ 隐式零扩展;若 b 是 signed,负数会变正
a = b + 8'd1;       // ❌ 混合位宽相加,结果宽度按最大,可能溢出
a = {4'b0, b};      // ✅ 显式零扩展
a = {{4{b[3]}}, b}; // ✅ 显式符号扩展
s = 8'(b);          // ✅ SystemVerilog 强制转换(明确知道在做什么)
```

- **跨位宽赋值**:用 `{N{x}}` 显式扩展,或 `$signed` / `$unsigned` / `8'(x)` 明确意图
- **混合位宽运算**:先对齐位宽再算,不要把不同宽度的操作数直接相加
- **减法/累加尤其注意**:无符号减无符号会回绕,不是负数
- **比较两侧位宽要一致**:`a == b` 里 `a` 8 位、`b` 4 位时,`b` 会被零扩展再比

**Verilator 报什么**:`WIDTH`(通用不符)/ `WIDTHTRUNC`(被截断)/ `WIDTHEXPAND`(被扩展)。
这三类**默认不在 `-Wall` 里**,本仓库的 `module-rtl-lint.mjs` 已显式开启 ——
所以它们会出现在输出里,**必须逐条判断**:确认是有意转换(写显式转换)还是 bug(改位宽)。

### 可综合代码禁用仿真构造

| 禁止 | 后果 |
|---|---|
| `#延时` | 综合忽略 → 仿真与硬件行为完全不同 |
| `initial` 做逻辑 | 上电初值不可控(BRAM 初始化例外) |
| `$display` / `$finish` | 报错或被忽略;必须包进 `` `ifndef SYNTHESIS `` |
| `force` / `release` | 仅调试用,综合不支持 |
| 动态数组 / 队列 / 关联数组 | 多数工具不支持;用固定深度数组 |
| `real` / `shortreal` | 综合不支持浮点;用定点 |

调试语句务必包住,否则综合报大量警告,也容易误留到量产:

```systemverilog
`ifndef SYNTHESIS
  $display("[dbg] state=%0d", state);
`endif
```

### 驱动方式:组合块用 `always_comb` 或 `assign`,一根信号只能一个驱动源

- **`always_comb` 优先**:自动推断敏感列表。用 `assign` 的前提是时序不退化(逐处对照综合结果,
  变差就保留 `always_comb`,理由写进块首注释)
- 必须写 `always @(...)` 时(旧风格),**敏感列表要覆盖所有读到的信号**：漏一个就综合出
  与仿真不符的电路(仿真按列表触发,综合按逻辑依赖)
- **一根信号只能一个驱动源**。上层 `assign` + 下层 `always_ff` 驱动同一根 = 多驱动,
  综合成线与/线或或直接报错。**模块边界上信号方向必须唯一**

### 例化尽量用命名连接

**优先命名连接(`.port(sig)`),少用位置连接。** 不做硬性要求 —— 但知道代价:

```systemverilog
// 位置连接:改一下端口顺序就静默连错,而且看不出来
sub_mod u_sub (clk, rst, din, dout, valid);

// 隐式连接:端口名对不上时工具只给 warning,连接就空着
sub_mod u_sub (.*);

// 命名连接:缺哪个、多哪个一眼看得出
sub_mod u_sub (
  .clk    (clk),
  .rst    (rst),
  .din    (din),
  .dout   (dout),
  .valid  (valid)
);
```

**位置连接的风险**:子模块端口增删/换序时静默连错 —— 仿真可能照样跑,只是行为不对。
Verilator 与综合工具的 unconnected / 宽度警告能抓到一部分,但不是全部。

**例外**:端口很少(2~3 个)且短期内不会变时,位置连接可读性更好;测试平台例化 DUT 不限定。

### 设计断言:每个 RTL 都要有

**不变量**用 SVA 断言写在模块内,声明区附近:

```systemverilog
// 状态机不得进入非法编码
property p_state_legal;
  @(posedge clk) disable iff (rst) state <= 3'd5;
endproperty
ap_state_legal: assert property (p_state_legal)
  else $error("[SVA] state=%0d illegal", state);
```

**三要素必写**(写在断言块上方的注释里):

| 要素 | 内容 |
|---|---|
| `Purpose` | 这条断言保护什么不变量 |
| `Trigger` | 什么条件下检查 |
| `Failure` | 违反时意味着什么(便于定位) |

**断言写完必须故意违反一次**,确认它真报错：不报错的断言等于没写。
SVA 写法与实测记录见 `fpga-module-verif` 技能的
`references/sva-as-formal-substitute.md`。

### generate 与参数化

- 重复逻辑用 `generate for`,不手写 N 份
- **`generate` 块加有意义的标签**(`gen_channel[i]`),否则综合报告层次名无法定位
- `localparam` 集中放模块顶部,含依赖参数推导的常量(`WIDTH_BYTES = WIDTH / 8`)

### 流水线与延迟对齐

- 只在时序需要的边界打拍：不是"每级都打",也不是"一次都不打"
- **打拍必须改信号名**(`_r` / `_d`),否则上下级同名,读代码分不清哪一拍
- **数据与 valid 必须同拍对齐**:反压路径错拍会丢数据;BRAM 读延迟固定 1 拍
  (或配置的流水级数),valid 要跟着延迟同样拍数,否则读到的数据与标志不匹配
- **BRAM 的读写冲突行为由 IP 配置决定**,不是代码决定：换配置行为就变

### 跨时钟域信号先过同步器再进逻辑

任何跨域信号**不得直接参与组合逻辑或状态判断**：必须先经同步器(两级触发器 / 异步 FIFO)
再使用。直接跨域仿真看不出问题,上板偶发失败。详见 [跨时钟域与复位](cdc-and-reset.md)。

## 附录:三个检查工具

### Verilator lint:查 `vlog` 不报的那一类

```
node "<自带命令目录>\module\module-rtl-lint.mjs" <模块根>
```

扫 `<模块根>/rtl` 下所有 `.v` / `.sv`。只查 `rtl/`,不查 `verif/`。

**它补的正是 `vlog` 看不到的**:

| 类别 | 含义 | 常见后果 |
|---|---|---|
| `UNUSEDSIGNAL` | 声明了没用 | **多半是拼写错或漏接** |
| `UNDRIVEN` | 没有驱动源 | 恒为 X/Z,静默传播到下游 |
| `WIDTHTRUNC` / `WIDTHEXPAND` | 位宽隐式截断 / 扩展 | 多数溢出 bug 的源头 |
| `LATCH` | `always_comb` 未覆盖全部路径 | 推出锁存器(见「避免 latch」) |
| `CASEINCOMPLETE` | case 没覆盖全 | latch 的前兆 |
| `MULTIDRIVEN` / `BLKANDNBLK` / `COMBDLY` | 多驱动 / 组合环 | 综合结果与仿真不一致 |
| `SELRANGE` | 位选越界 | 读/写到不存在的位 |

**这些在仿真里可能"碰巧跑对",改参数/换器件时才炸。**

**退出码**:0 = 无 error 且无重要 warning / 1 = 有问题 / 2 = 用法错 /
**3 = 环境不满足(BLOCKED)**。3 与 1 分开是有意的:**没有 msys2 bash 不等于代码有问题**。

#### Windows 路径陷阱(实测)

本机 Verilator 是 **msys2 包**,`VERILATOR_ROOT` 是 unix 路径。三种调用方式实测:

| 方式 | 结果 |
|---|---|
| `msys2 bash -lc 'export PATH=/mingw64/bin:$PATH && verilator …'` | ✅ **唯一可靠** |
| 直接调 `verilator_bin.exe` | `--version` 能跑,lint 报找不到 `verilated_std.sv` |
| perl 包装(Windows 直调) | `Can't exec "verilator_bin"` |

所以命令**固定走 bash**,没 bash 时退 3 并说明原因。设 `VERILATOR_ROOT` 也没用
(Verilator 按自己的安装布局编的,会报 "inconsistent path")。

#### XPM 与 IP:默认忽略缺模块

Vivado 的 XPM(`xpm_fifo_*` / `xpm_cdc_*`)和 IP 核不在 Verilator 库里,会报一堆 `MODMISSING`。
默认加 `-Wno-MODMISSING` 忽略,**但输出会明说「缺模块已忽略」**：别把那句当成「模块都找到了」。

要查缺模块(如怀疑漏了 `add_files`)时加 `--strict-modules`。

#### 警告处理

**警告必须解决,不许留着。**

唯一例外:`rtl/ip/` 下的厂商代码(那份不归本环节改)—— 在结论里单列一节,
说明属厂商代码、未修改。

**压制不是解决。** `-Wno-xxx` / `/* verilator lint_off XXX */` 只在厂商代码无法改、
或确认是工具误报时用,且须写明理由。「赶时间」「看着不影响功能」不是理由。

### 直接用厂商编译器时

用设置中选定的编译器。会话开头「本机 FPGA 工具链」已写明工具、路径与调用姿势,按那个执行。
下文以 Verilator 示例:

```powershell
& "<编译器路径>" --lint-only -Wall --top-module <顶层模块名> <文件...>
```

- 拆了子模块就**多个文件**:被例化的在前,按层级自底向上排：顺序错了会报"找不到模块",
  那不是代码写错
- 报 `module not found` 而该模块来自 IP(只有 `.xci` 或加密模型,没有可检查的 HDL)属正常:
  把该 IP 的端口 wrapper 一并传入,或**优先用 IP 自带的 `*_stub.v`**(就在 `rtl/ip/` 下,原地不动)。
  必须生成时,**生成物也要落回该 IP 目录**(`rtl/ip/<ip名>/<ip名>_stub.v`,
  如 `write_verilog -mode synth_stub`),**不许放到别处**：仿真的 `run.do` 只跳过
  `rtl/ip/` 下的 `*_stub.*`,放到别处会和真模型同名打架。**不得为通过检查而改动端口**
- 告警须清零;确需压制时在源码内**就地豁免**(`/* verilator lint_off XXX */` …
  `/* verilator lint_on XXX */`)并注明原因。**禁止用 `-Wno-XXX` 全局屏蔽**

### 机械检查:格式与结构

```powershell
node "<自带命令目录>\module\module-rtl-check.mjs" <模块目录>
```

覆盖文件头、九个小节块、端口类型、复位极性、always_ff、end/else、断言、制表符、行尾、
代码行非英文、测试平台自检,给出**行号**。要结构化结果加 `--json`。

**工具判不了、只能读代码判的三类**:

- **格式类(机械可判)**:禁用制表符;代码行限英文(注释除外);行尾统一,单文件内不混用
- **与依据一致**:端口对 `spec/spec.md`;实现路径对 `spec/flow.md`;参数取值对「参考资料」
- **结构类(须读代码)**:一个 always 块内混放不相关信号、断言是否正确、命名与结构

## 附录:工具查不到什么

- **功能对不对**(要仿真 + 断言 + 比对)
- **时序**(要综合 + `report_timing`)
- **跨时钟域**(Verilator 不查 CDC,见 [跨时钟域与复位](cdc-and-reset.md))
- **XPM / IP 内部**(不在它的库里)

**lint 通过 ≠ 设计正确。** 它的作用是在仿真之前把低级错误挡掉,省掉「仿真跑半天发现信号没接」这类往返。
