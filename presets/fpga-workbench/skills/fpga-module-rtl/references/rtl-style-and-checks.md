# 编译器检查与 RTL 规范清单

**总纲(用户口径):一切编写格式以时序最优为先。** 下面这些类型 / 字面量 / 命名 / 注释 / 分组 / 写法
都是**格式约定** —— 它们与"时序更好"冲突时,**让格式让步**,并在代码里写明为什么这么写。

## 第二步:编译器检查

**用设置中选定的编译器。** 会话开头「本机 FPGA 工具链」已写明是哪个工具、路径是什么,并给出该工具
的调用姿势 —— 按那个姿势执行,下文以 Verilator 为例:

```powershell
& "<编译器路径>" --lint-only -Wall --top-module <顶层模块名> <文件...>
```

- 只查 `rtl/` 下的源码(递归);`verif/` 下的仿真模型与测试平台不参与本检查
- 拆了子模块就**多个文件**:被例化的在前,按层级自底向上排(与仿真那节同一条)——
  顺序错了会报"找不到模块",那不是代码写错
- 报 `module not found`、而该模块来自 IP(只有 `.xci` 或加密模型,没有可检查的 HDL)属正常现象:
  把该 IP 的端口 wrapper 一并传入,或**优先用 IP 自带的 `*_stub.v`**(就在 `rtl/ip/` 下,原地不动)。
  确实没有自带的那份、必须生成时,**生成物也要落回该 IP 目录下**
  (`rtl/ip/<ip名>/<ip名>_stub.v`,用脚本生成即可,例如 `write_verilog -mode synth_stub`),
  **不许放到别处** —— 仿真的 `run.do` 只跳过 `rtl/ip/` 下的 `*_stub.*`,放到别处就会和真模型同名打架。
  **不得为通过检查而改动端口**
- 告警须清零;确需压制时在源码内**就地豁免**(`/* verilator lint_off XXX */` …
  `/* verilator lint_on XXX */`)并注明原因。**禁止用 `-Wno-XXX` 全局屏蔽**

## 第三步:逐条核对规范

**格式以模板为准**(见会话开头「本机 FPGA 工具链」的模板一节;未提供即插件自带那份),
核对前先读模板。

**机械部分先跑自带命令**(路径见会话开头「本模式自带的命令」):

```powershell
node "<自带命令目录>\module\module-rtl-check.mjs" <模块目录>
```

覆盖文件头、九个小节块、端口类型、复位极性、always_ff、end/else、断言、制表符、行尾、代码行非英文、
测试平台自检,并给出**行号**。要结构化结果时加 `--json`(平时不用加)。

工具判不了、只能读代码判的,对照下面三类:

- **格式类(机械可判)**:禁用制表符;代码行限英文(注释除外);行尾统一,单个文件内不得混用
- **与依据一致**:端口对 `spec/spec.md`;实现路径对 `spec/flow.md`;参数取值对「参考资料」。
  不一致就在这里说清为什么
- **结构类(须读代码判定)**:一个 always 块内混放不相关信号、断言是否正确、命名与结构

### 接口与内部信号:类型怎么定(用户口径)

| 位置 | 类型 | 例 |
|---|---|---|
| 模块 **input** | `wire` | `input wire [7:0] din` |
| 模块 **output** | `logic` | `output logic [7:0] dout` |
| 模块 **inout** | `tri` | `inout tri sda` |
| **内部信号** | `logic` | `logic [7:0] din_d;` |
| 内部**唯一例外** | `wire` —— **只**用于"实例与实例之间的连接网"(把某个实例的输出接到另一个实例的输入) | `wire [7:0] fifo_dout;` |

**函数 / 任务的形参不受上表限制**(那里的 `input logic x` 是变量,正常写法)。已有工程与外来代码的
既有写法**不为了统一而重排**。

### 字面量:每个都要带"宽度 + 基"(用户口径)

- **禁止 `'0`**(以及同族的 `'1` / `'x` / `'z`):它把宽度藏起来,位宽一改就静默对不上。
  清零 / 置全用**显式**写法:`{N{1'b0}}`;数组、结构清零用赋值模式 `'{default: 1'b0}`。
- 其余一律写全 `N'基值`:**信号类**(控制 / 握手 / 状态标志)统一用 **`'b`**(`1'b0`、`2'b10`);
  **数据类**(数据通路上的值)统一用 **`'h`**(`8'hA5`、`32'h1234_5678`);`'d` 留给纯整数语境。
- **例外**(可以照旧):`int unsigned` 的 `localparam`、循环变量、纯计数常量的十进制整数
  (如 `localparam int unsigned DEPTH = 16;`);确实必须不带宽度的场合,在代码里写明原因。

机械检查只查"**带没带**宽度与基"(它判不了这个信号是数据类还是信号类);"数据类用 `'h`、信号类用
`'b`"靠**读代码**判,写进结论。

### 信号名:精准、简练,后缀只表达"打拍"(用户口径)

**命名要精准而简练**:一眼看出它是什么 —— 不堆修饰词,也不靠后缀去暗示"这是组合还是寄存器"。

| 后缀 | 只用于 | 例 |
|---|---|---|
| `_r` | **单个控制类**信号(控制 / 握手 / 状态标志)的打拍版本 | `tvalid_r`、`tlast_r`、`tuser_r`、`col_r` |
| `_d` | **数据类**信号的打拍版本 | `crc_d`、`da_captured_d`、`fill_len_d` |

- **`_r` / `_d` 都只能加在寄存器上** —— 组合信号加这两个后缀就是错的
- **多级打拍**写 `_rr` / `_dd`(两级),或把几级并成**多位宽(数组)**形式;不要为每一级另造一个后缀
- **`_c` / `_v` 不用**(对组合信号没有信息量)
- **没有必要就严禁加后缀、别自己另造后缀形式** —— `_reg` / `_ff` / `_next` / `_n` / `_q1` 这类一律
  不写;确有别的含义(次态 / 下一拍要写入的值 `_nxt`、移位寄存器 `_sr`、进位 `_of`、求和 `_sum`、
  减一 `_m1`、测试平台驱动量 `_drv`)才用那个后缀 —— 不是为了"看得出是组合还是寄存器"
- **主寄存器(没有同名来源信号)不带后缀**(`tot_len`、`state`);`_cnt` / `_en` / `_valid` / `_hold`
  这种是**名字本身的一部分**(有含义),照常用

三条判定口径:

- **"是不是寄存器"看赋值,不看后缀猜**:看 `always_ff` 里的 `<=` 左值、或 `assign` 左值
- **同名孪生**:组合侧取**朴素名**、寄存器侧取**后缀**(`ev_rx_pkt` 组合 / `ev_rx_pkt_r` 寄存器)
- **引用方是端口(名字被冻结)时,组合侧取有含义的名字**(如 `tot_len_sum`);测试平台里与 DUT 端口
  重名的驱动量用 `_drv`

`_q`(老代码里"Q 端"的写法)**新代码不再用**:打拍的控制类写 `_r`、数据类写 `_d`。**已有工程与外来
代码里的既有命名不动** —— 不为改后缀去重排别人的代码。

**外来代码另行判断**:放在 `rtl/ip/` 下的厂商 IP 与他人模块,机械检查**跳过**(它们不按本模块的
格式规范书写)。这类代码的报错先与用户确认是否要改,**不得擅自重排厂商代码**。

### 注释:长度、块首与例外

- **设计说明 1~2 行、至多 3 行**;**端口分组注释同样按 3 行办** —— 超出的细节移到块级注释或设计说明
  里,不要靠长注释解释接口
- **设计 RTL 里,每个 `always` / `always_ff` / `always_comb` / `initial` 块有且仅有一条块首注释**,
  写清这个块在干什么;不要给它写第二条、也不要让块首领错对象
- 三类**例外**(模板强制的块,不受 3 行限制):文件头、`L12` 的模块简介、断言里的
  `Purpose :` / `Trigger :` / `Failure :` 块

### 声明区:位置与分组(用户口径)

**位置**:声明区里**先寄存器、后组合** —— `// ---- Registers (sequential state) ----` 在前,
`// ---- Combinational ----` 在后,两段各自按功能分组。

**分组**:每组**一条**注释,形制统一写 `//--- 组名 ---`(旧的散文式分组注释换成这个形制);
**新增信号归到对应的组里**,不要随手加在段末。**端口同样按功能分组**(clock/reset 一组,其余按接口
语义),形制与声明区一致。

**组合逻辑区按数据流顺序摆**:如 仲裁 → 源握手 → 输出接受与捕获 → 头部拼装 → 输出多路选择 ——
让人顺着数据流读下来。

### 组合逻辑:尽量用 `assign` 而不是 `always_comb`(用户口径)

**尽量用 `assign` 而不是 `always_comb`** —— 前提是**时序不退化**:逐处改、逐处对照综合结果,
不变差才换,**实测变深的就保留 `always_comb`** 并把理由写在块首注释里(别让后人再试一遍)。
跟上面那条总纲一致:写法听时序的,不听"看起来更组合"的。
