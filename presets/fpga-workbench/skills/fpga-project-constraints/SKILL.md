# project-constraints:约束与管脚

**本环节出错会损伤硬件。** 管脚分配错、IO 电平错,上板可能直接损坏器件或外设 —— 所以这里的
规矩比别处严:**逐条核过,不许"应该是这样"**。

不过"严"是**针对要上板的那些约束**,不是每次都把全部管脚重核一遍:

- **起草/分析约束**随时可以做(读原理图、对着器件手册写 XDC、检查现有一致性)。
- **内部逻辑改动**(改算法、改状态机、改位宽)不自动触发重新核管脚 —— 只要对外的管脚、
  电平和时钟没动,原来核过的那份就还算数。
- **真正要上板之前**,对着原理图与器件规格把受影响的管脚、电压、IO 标准再核一遍(见
  `fpga-project-board`)。

## 做什么

1. **时钟约束**:每个时钟一个 `create_clock`,周期取设计真实目标(不是随手填的整数)
2. **管脚分配**:**对着原理图**一条一条核 —— 信号名 ↔ 管脚号 ↔ IO 标准 ↔ 上下拉
3. **IO 标准与电平**:电压标准必须与外设一致(原理图上会标);不确定即询问,不得猜测
4. **时序例外**:`set_false_path` / `set_multicycle_path` 每一条都要写**为什么** ——
   例外是"已知这里不用按常规时序收敛",并非"借此消除报错"
5. **时序例外与时序目标分清楚**:参考周期是分析输入;真正的目标来自板子与接口协议

> ⚠️ **XDC 里不能写 Tcl 控制流**(`if` / `source` / `file`)。
> XDC 会 CRITICAL WARNING 后**静默跳过**那条约束,现象是"没有时钟"或管脚没生效 ——
> 不报错,最难排查。

## 判据

- **PASS**:约束文件被 Vivado 接受(`constraint_status = PASS`);管脚逐条与原理图核对过;
  没有未约束的 I/O;每条时序例外都有理由
- **FAIL**:管脚与原理图不符、IO 标准不对、有时序例外但没写理由、有未约束的 I/O
- **BLOCKED**:拿不到原理图或管脚表 —— 那本环节**过不去**,如实说,不得凭接口名猜管脚
- **NOT_APPLICABLE**:这次不涉及新的管脚(比如只改了内部逻辑)

## 产物

写 `<工作区根>/project/constraints/constraints.md`:

- 结论(`PASS` / `FAIL` / `BLOCKED` / `UNVERIFIED` / `NOT_APPLICABLE`)+ 约束文件路径
- **管脚对照表**:信号名 | 管脚号 | IO 标准 | 来源(原理图第几页/哪个连接器)
- 时钟清单:名字、周期、来源
- 时序例外清单:哪条路径、为什么、谁确认的
- 没核到的管脚**列出来**(不得沉默略过)

## 停下来问用户的时候

- 原理图拿不到,或者上面标的不清楚
- 同一管脚有两种可能接法
- 要放宽约束才能收敛 —— 那是设计问题,不是约束问题,先问
