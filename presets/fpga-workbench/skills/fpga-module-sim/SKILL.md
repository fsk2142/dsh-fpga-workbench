# module-sim:功能仿真

**可反复进出**:仿真失败 → 改 RTL 或测试平台 → 再跑,轮次不限。一次 FAIL 只表示本轮未通过,
不表示本环节结束。工具不可用时也**不得伪造结果** —— 可读代码、分析原因、写好待跑的测试平台,
并明确标注"未验证"。

## 前置

1. 找约定文件 `.fpga-workbench.json`(模块根);找不到则询问用户,见 `fpga-module-spec`
2. 读 `spec/spec.md`:接口、时钟、AC、比对方案(输入/输出路径与格式)在其中 —— 测试平台照着它写
3. **spec 里若做过 Python 原型**(`spec/explore/` 下,spec 的「参考资料」一节点名了它):
   其输入可作激励,其输出可作期望值 —— 拿它做自检远比人工填写期望值可靠。
   但**本次仿真的证据须自行跑出**:原型那次运行不计入本轮结果
4. **建议**先看 `rtl/lint.md` 是不是 PASS(先过机械检查可省下大量仿真排错时间)—— 但正在排查
   仿真问题、或用户就是要先看仿真行为时,不必停下补 lint
5. 测试平台也**不要手抄模板** —— 用自带命令起文件(命令名就是环节:`sim-new`):

   ```powershell
   node "<自带命令目录>\sim-new.mjs" <模块根> <模块名> --template "<测试平台模板路径>"
   ```

   默认落 `sim/tb_<snake>.sv`(`<snake>` 是模块名的下划线形式:`UartRx` → `tb_uart_rx`;
   脚本只替模块名,与 `fpga-module-rtl` 同一条,要另换位置用 `--out`)。扩展名跟着模板走,
   所以先在设置里选对**仿真语言**(SystemVerilog → `.sv` / Verilog → `.v` / VHDL → `.vhd`);
   自带模板是 SystemVerilog 的,要写别的语言得自己准备对应语言的模板。起完文件再按模板结构填逻辑。

**没有测试平台 ≠ 仿真"不适用"**:若当前目标就是验证功能,则属 `UNVERIFIED` 或
`BLOCKED`(缺工具/缺平台),不是 `NOT_APPLICABLE`。通常答案是把测试平台写出来。

## 跑一次仿真(全程命令行,不弹图形界面)

下面的例子按 **SystemVerilog**(`.sv`)写;选了 Verilog / VHDL 就把文件扩展名换成 `.v` / `.vhd`,
编译命令也换成对应语言的形式(`vcom` 对应 VHDL,`vlog`/`xvlog -sv` 对应 SV)。

**先用设置里选定的仿真器** —— 看会话开头「本机 FPGA 工具链」的**已就绪清单**:仿真器是
ModelSim / Vivado XSim / Verilator、路径是什么,都写在那里。**不得另行挑选一个。**

**ModelSim / Questa(默认)**

```
cd <模块根>/sim
vdel -lib work -all          # 有旧 work 库先删除,不在残留库中编译
vlib work
vcom -2008 <VHDL 文件...>    # 只有混语言模块才需要
vlog -sv <源码...> <tb_*.sv>
vsim -c -voptargs="+acc=rn" tb_<模块名>
run -all
quit -f
```

**Vivado XSim**(选了它就用 Vivado bin 目录下的这三个命令)

```
cd <模块根>/sim
xvlog -sv <源码...> <tb_*.sv>
xelab -debug typical tb_<模块名> -s tb_sim
xsim tb_sim -runall
```

**Verilator**(只适合 lint 与快速回归:**没有时序**,不能拿来代替功能仿真)

```
"<仿真器路径>" --binary --timing -Wall --top-module tb_<模块名> <源码...> <tb_*.sv>
./obj_dir/Vtb_<模块名>
```

通用的几条:

- **`-c` / `-runall` 这类批处理开关必须加** —— 不加会弹出图形界面等人操作,无人值守就跑不下去
- **编译顺序:被例化的在前**。文件多了按层级自底向上排;顺序错了编译会报未解析的模块
- 需重复跑就写成一个脚本(`run.do` / `run.tcl`),命令原文随结果文件一并保存
- 多个测试平台按 `tb_sub_*` → `tb_*` → `tb_top_*` 的顺序各起一个进程(每个 `$finish` 结束一个进程)

## 测试平台必须有的三样(缺一样,这次仿真就不算数)

自检、最终判定、看门狗这三样的写法自带 `tb.sv` 里都有(照它写即可),这里只讲判据本身:

- **失败必须让退出码非零**:判定要 `$fatal(1, ...)` —— **只 `$display` 一句 FAIL 是不行的**,
  脚本抓不到失败,这条是硬红线
- **判定要能自动做**:每处不符 `$error(...)` 并累计,别让"通过与否"靠人看波形
- **超时要有人管**:没有看门狗,挂死的仿真会一直挂着,无人察觉

## 输出数据:格式是红线

比对数据(如果这个模块有)写到 `spec` 里确认过的路径与格式,**不得自行改文件名或后缀**。

写十六进制要写**大写文本**:`$fwrite`/`$fdisplay` **不许用 `%x` / `%h`** —— 用 `%c` 加 ASCII 运算拼字符
(模板里有 `upnib` 函数)。原因很实际:比对按文本逐字节比,`%x` 的宽度与对齐不受控。

## 用什么模型

用 `sim/` 里**真实的** IP 仿真模型(自建或用户提供的都在这里),不许拿简化版或快速桩顶上。
仿真用桩、综合用真 RTL,
两边行为一旦不一致,排查将十分耗时,且结论不可信。

## 判据

- **PASS**:`err_cnt = 0`,日志里出现成功标记,进程退出码 0
- **FAIL**:非零退出,或日志里出现 `$error` / `$fatal`,或超时 `TB TIMEOUT`
- **BLOCKED**:vsim 没就绪(设置里标了「未就绪」)→ 如实说明并停下,不得假装跑过
- **UNVERIFIED**:`sim/` 下还没有测试平台(`tb_*`)—— 见上面「没有测试平台 ≠ 仿真不适用」
- **NOT_APPLICABLE**:只有这个模块**本来就没有可仿真的行为**(例如纯约束 / 纯管脚类改动),
  已说明理由才算

挂死或超时时,先怀疑:时钟没起、复位没放、握手没接上、位宽对错。**不得第一反应就是调大看门狗。**

## 产物

写 `<模块根>/sim/sim.md`:

- 结论(`PASS` / `FAIL` / `BLOCKED` / `UNVERIFIED` / `NOT_APPLICABLE`)
- 跑过的**命令原文**(或该 `run.do` 的路径),可直接复制复现
- PASS 时:成功标记那一行原文
- FAIL 时:错误列表 + 日志路径 + 判断的原因(以及改了什么)
- 覆盖了哪些 AC、哪些没覆盖(没覆盖就写"未覆盖",不得写"应该没问题")

测试平台源码(`tb_*` 与脚本,扩展名按仿真语言)与本次结果(日志、波形、输出数据)都放 `sim/`,
按文件名区分;不要另建源码目录,也不要只把结果落在这里而把源码留在别处。

本环节只能证明"逻辑符合测试平台"。时序与上板不在本环节范围内。
