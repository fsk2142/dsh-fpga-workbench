# X 初态仿真：让上电的不确定性在桌面上暴露

> 全 X 初态仿真的目的：把「依赖初值」这类假设在桌面上提前打破，
> 而不是留到上板后用二分法逼近。

## 为什么这一项值半天工时

真实 FPGA 上电后，触发器内容由综合与实现工具的初值策略决定，**块存储器（BRAM）
内容则完全不确定**。

而绝大多数 testbench 从 0 开始，造成两类掩盖：

### 掩盖一：缺失的复位

未写复位的寄存器在仿真中因初值为 0 而表现正常。上板后初值可能是任意值 ——
综合工具可能把它映射到 LUT（初值 0）、映射到带初值的专用单元、甚至优化掉。
状态机在这种不确定性下直接进入非法状态。

### 掩盖二：未初始化的存储器

BRAM 未初始化即被读取，仿真读到 0 不报错；硬件读到随机数据，导致后续计算全错
或保护逻辑误动作。

**更隐蔽的情况**：读到的随机数据恰好构成一个「看起来合法」的包头，
协议解析器进入错误分支 —— 故障现象与真正的问题完全不相干。

## 三档做法

| 档 | 做法 | 说明 |
|---|---|---|
| 一 | 仿真器全局寄存器初值 | **本机不成立**，见下 |
| 二 | **存储器 / FIFO 的 X 化** | **最重要**，仿真器选项覆盖不到 |
| 三 | X 传播检查（`-xprop`） | 补强，需区分真未初始化与合法不关心 |

### 第一档：为什么在本机不成立

网上流传的写法是 `vopt +acc -initreg +X`。**实测（ModelSim 2020.4）直接报错**：

```
** Error (suppressible): (vopt-10538) Option "-initreg" is not a valid option for this tool.
```

`vopt -help` 里**完全没有 initreg 字样**。那是较新 Questa 的语法。

而 ModelSim 的**默认行为本身就是全 X**：

| 配置 | 时刻 0 的探测结果 |
|---|---|
| 不 vopt | 全 X |
| `vopt -O0` / `-O1` / `-O5` | 全 X |
| `vopt -initreg0` | （选项不合法） |

**注意**：`-initreg0` 若在某些版本可用，它是把寄存器**强制成 0**，正好抹掉 X ——
方向是反的，不是我们要的。

所以第一档不需要做 —— **ModelSim 默认就保留 X**。真正掩盖 X 的是
testbench / RTL 里自己写的初值。

### 第二档：存储器 X 化（必须手工）

仿真器的全局初值选项**不覆盖** BRAM 和 FIFO 的存储数组，而这是 X 的第一大来源。

```systemverilog
// 存储器：仅在仿真编译时生效
`ifdef SIM_INIT_X
  integer xi;
  initial begin
    for (xi = 0; xi < MEM_DEPTH; xi = xi + 1)
      mem[xi] = {DATA_W{1'bx}};
  end
`endif
```

**FIFO 要把读写指针一起 X 化**：

```systemverilog
`ifdef SIM_INIT_X
  initial begin
    for (xi = 0; xi < FIFO_DEPTH; xi = xi + 1)
      fifo_mem[xi] = {WIDTH{1'bx}};
    wr_ptr = 'x;
    rd_ptr = 'x;
    count  = 'x;
  end
`endif
```

只 X 化数据数组、指针仍从 0 开始，两者不一致会产生难以解释的现象。

#### 必须豁免的两类（否则变成噪声源）

1. **有初始化文件的 BRAM**（`.coe` / `.mif` / `$readmemh`）—— 硬件上确有确定初值，
   做 X 化只会产生大量假阳性
2. **纯只读表**（名字含 `rom` / `const` / `lookup`）—— 通常配初始化文件

要区分「设计上依赖初始化」和「设计上不依赖初始化」：前者应改为通过配置寄存器写入，
或明确使用初始化文件。

### 第三档：X 传播检查

默认情况下仿真器对 X 的处理过于乐观：

- `if (x)` 会静默走 `else` 分支
- `case (x)` 可能命中某个分支
- `combinational x & 0` 被优化为 `0` 而不是 `x`

开启后 X 沿逻辑真实传播，把隐藏的未初始化路径暴露出来。典型选项
（**不同仿真器名称不同，以该版本命令参考为准**）：

```bash
# VCS
vcs -sverilog -xprop=tmerge -f filelist.f
#   tmerge : 更精确的 X 合并语义（推荐）
#   xmerge : 更保守，会把更多组合逻辑输出判为 X

# Questa（ModelSim 的选项名可能不同，需实测确认）
vopt +acc -xprop=tmerge tb -o tb_opt
```

开启后可能出现大量「误报」X，需要区分「真未初始化」与「合法的不关心态」。

## 判据

不只是「跑过」，四条都要满足：

| 判据 | 具体要求 | 不满足怎么办 |
|---|---|---|
| **行为一致性** | 全 X 初态下的回归结果与 0 初态**完全一致** | 定位到首个出现差异的用例，查它依赖的初值来源 |
| **X 可解释性** | 出现的每一个 X 都能归因为「合法的未初始化」而非逻辑泄漏 | 记录豁免清单，逐条写明该 X 为何不影响功能 |
| **复位完备性** | 所有状态机、所有带反馈的寄存器链，复位后进入确定状态 | 补复位或改用可自同步的编码 |
| **存储器初始化** | 所有存储阵列被读之前，要么已写入，要么处于明确的不关心状态 | 补初始化，或在协议层保证读前必写 |

## 典型陷阱

| 陷阱 | 表现 | 正确做法 |
|---|---|---|
| **用 `force` 绕过** | 为通过全 X 测试，在 TB 里给 DUT 内部信号强制赋值 | 等于把要检验的假设又加回去了。应改 RTL，不是掩盖 |
| 只处理顶层 | 只对顶层寄存器 X 化，子模块内部存储数组仍是 0 | 确保覆盖所有层级，**包括 IP 核内部的存储器** |
| X 噪声多了就关掉 | 开启 X 传播后报告大量 X，于是整体关闭 | 建豁免清单，逐条说明哪些 X 合法 |
| 忽略初始化文件 | 对 `.coe` 初始化的 BRAM 也做 X 化，大量假阳性 | 区分「有初始化文件」与「无初始化文件」两类 |
| 只在首次跑 | 只在新功能开发时跑一次，后续回归不含 | 把全 X 仿真作为回归的**标准配置**，每次都跑 |

## 成本与收益

**实施成本**：半天到一天。

**典型收益**：提前发现「上电即死」类问题的绝大部分。

这类问题留到上板，通常要数天才能定位 —— 硬件上没有信号可见性，
只能靠反复改代码、重新综合、下载，用二分法逼近。
