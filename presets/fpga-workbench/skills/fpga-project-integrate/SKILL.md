# project-integrate:顶层集成

## 前置(区分早期集成与正式验收)

**早期集成随时可以做**:搭顶层骨架、试接接口、跑一次 elaborate 看连不连得上、定位集成问题 ——
这些不需要等模块全部验证完。此时代价很低,收益是把接口问题尽早暴露出来。
**唯一的要求是标注清楚**:哪些模块尚未验证、风险何在。未验证的模块接进去,后续出问题时
分不清是模块的错还是接线的错 —— 所以必须标出来。

**正式集成验收**(往交付方向走的那一步)才要求:

- 该模块的 `rtl/`(机械检查结论在 `rtl/lint.md`)、`verif/`(测试平台与比对结论)**都是 `PASS`**,
  或是有依据的 `NOT_APPLICABLE`
- 有审查结论就一并看(`<模块根>/review.md`,按需产出);没有审查,各环节的 `PASS` 就是最低证据

**`BLOCKED` / `UNVERIFIED` 不等于"有结论"**:它们只说明当时没验成,不构成通过。
另外,**写在结论文件里的话不等于事实** —— 遇到状态存疑(比如某处的 `BLOCKED` 理由是"工具没就绪")
先去核实那条理由是否成立:理由不成立时,真实状态要按实测重新记(实测 FAIL 就是 FAIL),
不得拿一条站不住的 `BLOCKED` 当通行证。

状态不清时**如实说明并问用户**,不得假装它已经验过。

> 不是每个模块都会进工程 —— 只做交付物的模块(供他人使用的 IP)跑完模块级就算完成。
> 这里只管**工程 spec 的模块清单表里列出的**那些。

## 干什么

1. **选顶层**:工程顶层(`*_top`)在哪,把模块实例化进去
2. **模块从哪来**:每个模块**先问用户是提供还是由本环节写** —— 用户已有 / 他人提供的收下直接用
   (`rtl/` 下,与自己的代码同等对待),来源与版本写进 `project/spec/spec.md` 的「参考资料」。
   **不要在集成时自己另写一个顶上**,也不要默默改模块的接口去迁就顶层
3. **时钟与复位**:每个模块用哪个时钟、复位的来源与极性、跨时钟域在顶层怎么处理
4. **接口对接**:位宽、符号、协议、握手方向 —— 逐条核对,不得以"大致相符"为由略过
5. **加进工程**:源文件加进 Vivado 工程的 srcs;IP 加到工程里(按器件选对应目录)
6. **连通性**:跑一次 elaborate 或综合,确认没有未连接端口、没有多驱动、位宽不匹配

## 本环节要跑的命令

集成本身是编辑工作(改顶层、接接口),真正要跑的是**连通性检查**:

| 干什么 | 命令 |
|---|---|
| elaborate / 综合看连通性 | Vivado 批处理:`open_project <工程>` → `launch_runs synth_1`(或 `synth_design -rtl` 只做 elaborate) |
| 机械规范(**顶层自己那份代码**) | `node "<自带命令目录>\module\module-rtl-check.mjs" <顶层所在目录>` |
| 机械规范(**各模块**) | 对模块清单里每个模块各跑一次:`module-rtl-check.mjs <模块根>` —— **不能拿工作区根当参数** |
| 看波形(定位接口问题时) | 用该模块**已经确认过的那份脚本**起 GUI(ModelSim 是 `verif/run.do`,选了 XSim 就是 `xelab` 出来的 snapshot;见 `fpga-module-verif` 第三步) |

**注意 `module-*` 命令的参数是模块根,不是工作区根**:工程根下平铺着 `project/` 与多个模块目录,
把工作区根传进去只会扫到不相干的东西(它的判据是"一个模块的源码目录")。

**早期集成**只跑 elaborate 就够(便宜、快);**正式验收**要求模块级结论齐(见「前置」)。

## 判据

- **PASS**:elaborate/综合能过;顶层没有未连接或悬空端口;跨时钟域的地方在顶层有明确处理
  —— **正式验收**时还要求相关模块的模块级结论齐(见上)
- **FAIL**:位宽/符号对不上、多驱动、少连时钟复位、跨域没处理
- **BLOCKED**:要正式验收,但某个模块没有 PASS 结论(`BLOCKED` / `UNVERIFIED` / 结论文件缺失都算)
  —— 前置不成立
- **UNVERIFIED**:骨架搭好了、还跑不了(模块未完成/工具没就绪)—— 如实记,不要写成 PASS
- **NOT_APPLICABLE**:这次没有要集成的模块(纯顶层改动)

## 产物

写 `<工作区根>/project/integrate/integrate.md`:

- 结论(`PASS` / `FAIL` / `BLOCKED` / `UNVERIFIED` / `NOT_APPLICABLE`)+ 每个模块的实例名
  (顶层文件里的例化名)
- **接线表**,一行一个接口:

  | 模块 | 实例名 | 时钟 | 复位 | 接口 → 对端 |
  |---|---|---|---|---|

- 跨时钟域的地方:哪两个域、怎么处理的
- 跑过的命令原文 + 日志路径(能复现)
- 没接完或临时悬空的地方:**明确写出来**,不要留个 TODO 就不提

## 常见坑(按踩到的频率排)

- 位宽与符号:接了但少一位、或补错符号位 —— elaborate 不报错,到仿真才暴露
- 时钟域:两个模块表面上使用同一时钟,实际一个是分频出来的
- 复位:一个模块高有效、一个低有效,顶层直接接过去
- 例化名与文件名不一致,后续定位信号困难
