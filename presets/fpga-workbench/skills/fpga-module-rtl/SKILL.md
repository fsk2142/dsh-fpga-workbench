# module-rtl:编写、编译检查与规范核对

本环节把**已确认的规格**落成 RTL。写什么不是自由发挥 —— 依据三份东西,写在前面:

| 依据 | 取什么 |
|---|---|
| `spec/spec.md` | 端口、位宽、时钟与复位、验收判据(AC)、指标(吞吐 / 延迟 / 反压) |
| `spec/flow.md` | **实现路径**:数据通路、状态机跳转、握手与反压、时钟域、流水级数与拍数 |
| `spec/spec.md` 的「参考资料」一节 | 算法、参数取值、定点位宽 —— 有原型或文档就照它,别凭感觉 |

**图与规格就是"怎么做"的定稿。** 实现中发现图走不通、或规格没写清:先跟用户说清,回去改
`spec/flow.md` / `spec/spec.md` 并重新确认,再接着写 —— **不要默默换一条路径自己写下去**,
那样的代码没人能对着图复核。

下面是本环节的三步:起文件并写逻辑 → 编译器检查 → 逐条核对规范。**写完之后**再一起跑检查,
跑哪些命令、为什么这么排,见文末「跑什么、什么时候跑」。

## 前置

1. 找约定文件 `.fpga-workbench.json`(模块根;找不到则询问用户,见 `fpga-module-spec`)
2. **读齐上面三份依据**:`spec/spec.md`、`spec/flow.md`、以及 spec 里点名的参考资料(原型 / 文档)。
   规格里没提到的实现细节,属于要回去问的事,不要自己定
3. 待查源码按设置里选定的 RTL 语言取:`rtl/` 下的 `.sv` / `.v`(递归)。
   源码为 VHDL 时本检查器不覆盖 → 结论记 `NOT_APPLICABLE` 并说明原因,**不得视为通过**

## 第一步:用模板生成文件,再编写逻辑

**不要从空文件写起,也不要手抄模板。** 用自带命令把模板复制成目标文件(命令名就是环节:`rtl-new`):

```powershell
node "<自带命令目录>\rtl-new.mjs" <模块根> <模块名> --template "<RTL 模板路径>"
```

- 模板路径取设置里配好的那份(见会话开头「本机 FPGA 工具链」的模板一节;留空即插件自带那套)
- 落点固定为 `rtl/<模块名>.<模板扩展名>`
- **脚本只替模块名**(`<ModuleName>` / `<module_snake>`),其余内容原样保留 —— 模板千差万别,
  日期、作者、版本这些按模板自己的规矩来,不要靠脚本替
- 生成后在文件里**改该改的地方**,并往里填逻辑:
  - **接口照 `spec/spec.md` 抄准**(端口名、方向、位宽、复位极性);**实现路径照 `spec/flow.md`**
    (数据通路与流水级数、状态机、握手与反压、跨时钟处理按图里定的来)
  - 算法与参数照「参考资料」(原型跑出来的参数、定点位宽、边界处理);**没有参考就问用户**,
    不要凭感觉定关键参数
  - **一个文件写不完整块逻辑就拆成子模块**(判据见下面「一个模块拆多个文件时」);
    要用到现成的子模块,**先问用户是提供还是由本环节写**
  - 模板里没替的占位符(如 `<DATE>` / `<Author>`)按本模块的实际情况填上
  - 各 `TODO` 换成真实参数、端口、逻辑
  - 文件头字段与功能说明写实;九个小节块按模板保留;断言连 Purpose / Trigger / Failure 一并写
- 模板里已经写好的不要再另立一套:`` `resetall `` / `` `timescale `` / `` `default_nettype none ``、
  `end else begin` 同行、端口名与类型对齐至第 69 列
- 要写的语言没有对应模板时(自带模板是 SystemVerilog 的),照它的**结构**自己起一份 ——
  这种情形没有可复制的模板,脚本用不上

### 一个模块拆多个文件时

- **什么时候拆**:一个文件写不完整块逻辑时**必须拆**(文件里塞不下、或塞进去没人看得懂),
  拆成子模块,不要硬塞在一个文件里。**能不能塞下不是拆不拆的判据** —— 依据是
  `spec/flow.md` 那张图里的功能块;图上本来就是几块,就应该有几个模块
- **每个子模块一个文件**:文件名 = 模块名(与 `module <名字>` 一致),都平级放 `rtl/` 下
- **用到的其他模块 / 现成的子模块**:**先问用户**——这个子模块你来提供,还是由本环节来写?
  不要自行假定,也不要默默自己写一个顶上:
  - 用户提供 → 收下直接用(`rtl/` 下,与自己的代码同等对待);**来源与版本**写进 spec 的
    「参考资料」,后面比对与上板时能对上
  - 用户没有、要自己写 → 按本环节的规矩写,同样放 `rtl/`
  - **不得为了绕开依赖而把现成的子模块重写一遍**
- 顶层(本模块若是个小系统)与子模块平级:`rtl/<模块名>.<扩展名>` + `rtl/<子模块名>.<扩展名>`
- `rtl/ip/` 只放外来代码(厂商 IP、他人提供的模块),自己的代码不放进去

### 需要 IP 核时:先问用户,再按用途归位

编写过程中要用到 IP 核(厂商 IP、需生成的功能块、他人提供的模块)时:

1. **先问用户**:这个 IP 由你生成,还是你来提供?**不要自行假定**,也不要默默换一个实现绕过它
2. **用户要自己生成** → 由本环节建:
   - 逻辑简单(一个小 FIFO、一个计数器之类)→ 直接在 `rtl/` 里自己写,不必走厂商 IP 流程
   - 要用厂商 IP → 用工具生成(如 Vivado 的 `create_ip` + `generate_target`),
     **生成脚本与 `.xci` 一并入档**(可复现),不要只在图形界面点出来
3. **用户提供** → 收下并按下面的规则归位,来源与版本写进 spec 的「参考资料」

归位规则(生成完或拿到后按用途拆开):

- **仿真用的文件**(仿真模型、厂商仿真库、行为级模型)→ `sim/`
- **RTL 与综合用的部分**(RTL 封装 / wrapper、自己写的那部分、`.xci`)→ `rtl/ip/`

所以同一个 IP 可能同时出现在两处:`sim/` 放它的仿真模型,`rtl/ip/` 放综合用的实体。归位之后
在 `rtl/lint.md` 或 spec 里记一句走了哪条路(自建 / 用户提供),后面比对与上板时能对上型号与版本。

## 第二步:编译器检查

**用设置中选定的编译器。** 会话开头「本机 FPGA 工具链」已写明是哪个工具、路径是什么,并给出该工具
的调用姿势 —— 按那个姿势执行,下文以 Verilator 为例:

```powershell
& "<编译器路径>" --lint-only -Wall --top-module <顶层模块名> <文件...>
```

- 只查 `rtl/` 下的源码(递归);`sim/` 下的仿真模型不参与本检查
- 拆了子模块就**多个文件**:被例化的在前,按层级自底向上排(与仿真那节同一条)——
  顺序错了会报"找不到模块",那不是代码写错
- 报 `module not found`、而该模块来自 IP(只有 `.xci` 或加密模型,没有可检查的 HDL)属正常现象:
  把该 IP 的端口 wrapper 一并传入,或临时生成只含端口的黑盒 stub 加入命令行。
  **不得为通过检查而改动端口**
- 告警须清零;确需压制时在源码内**就地豁免**(`/* verilator lint_off XXX */` …
  `/* verilator lint_on XXX */`)并注明原因。**禁止用 `-Wno-XXX` 全局屏蔽**

## 第三步:逐条核对规范

**格式以模板为准**:RTL / 测试平台 / 约束各有模板(见会话开头「本机 FPGA 工具链」的模板一节;
未提供即插件自带那份),核对前先读模板 —— 哪些属于模板已定好的,见下面的「结构类」。

**机械部分先跑自带命令**(路径见会话开头「本模式自带的命令」):

```powershell
node "<自带命令目录>\rtl-check.mjs" <模块目录>
```

覆盖文件头、九个小节块、端口类型、复位极性、always_ff、end/else、断言、制表符、行尾、代码行非英文、
测试平台自检,并给出**行号**。退出码 0 = 无阻塞项(可能仍有警告)/ 1 = 有阻塞项 / 2 = 用法或环境问题。

工具判不了的须自行读代码:一个 always 块内混放不相关信号、断言是否正确、命名与结构。

核对结果对照下面两类规则;书写时就按它们来,本环节只做写后核对。

**格式类(机械可判)**

- 禁用制表符
- 代码行限英文(注释除外)
- 行尾统一,单个文件内不得混用

**与依据一致(须对着 spec 与图核)**

- 端口与 `spec/spec.md` 一致:名字、方向、位宽、复位极性、时钟
- 实现路径与 `spec/flow.md` 一致:状态机与跳转条件、握手与反压、流水级数与拍数、跨时钟处理
- 参数取值与「参考资料」一致(原型或文档);不一致就在这里说清为什么

**结构类(须读代码判定)**

**模板已经定好的(别另立一套)**:文件头字段、开头/结尾那些指令、端口声明与对齐、
`end else begin` 同行、九个小节 banner 及其排法 —— 起文件时就是复制模板,这些照模板即可。
上面第三步的机械检查会查它们(所以不是"不用管",而是"不用在这里再抄一遍");换了模板以模板为准。

**写代码时自己把住**

- 复位高有效 —— 模板里 `if (rst)` 是对的,别写成 `rst_n`、`!rst` 或 `negedge rst`
- `always_ff` 仅用 `posedge`
- 每个 RTL 须有设计断言,并写明 Purpose / Trigger / Failure
- **一个 always 块内不混放不相关信号** —— 除非共用同一套控制逻辑(同一状态机、同一事务生命周期、
  同一寄存器组)。无法说明其共同控制关系时拆分
- 测试平台须含 `$fatal` / `$error`:仿真失败须能被自动捕获,不得依赖人工观察波形

**外来代码另行判断**:厂商 IP、他人提供的模块放在 `rtl/ip/` 下(仿真模型放 `sim/`,见第一步)——
机械检查**跳过 `rtl/ip/`**(它们不按本模块的格式规范书写)。这类代码的报错先与用户确认是否要改,
**不得擅自重排厂商代码**。

## 跑什么、什么时候跑

**时机:三步都写完之后跑,不逐文件跑。** 一次编译要展开全部文件,逐文件运行等于把同一次编译拆成
很多次;报错集中在一轮里定位与修改,也比来回切文件快。

| 跑什么 | 命令 | 看什么 |
|---|---|---|
| 编译器检查(第二步) | `& "<编译器路径>" --lint-only -Wall --top-module <顶层模块名> <文件...>` | error / warning,判法见第二步 |
| 规范核对(第三步) | `node "<自带命令目录>\rtl-check.mjs" <模块目录>` | 退出码与带行号的条目,判法见第三步 |

- `rtl-check`(上表第二条)会顺带查一眼 `sim/tb_*` —— 所以"这一轮全绿"包含测试平台的机械规范,
  **第一次跑仿真前那部分也该是干净的**
- 退出码 0 = 无阻塞项 / 1 = 有阻塞项 / 2 = 用法或环境问题(如 `rtl/` 下没有源码、纯 VHDL 不在
  检查范围内)。**2 不是通过**:按前置第 3 条如实记 `BLOCKED` 或 `NOT_APPLICABLE` 并说明原因
- 两条命令的完整输出都记进 `rtl/lint.md`,结论与 `文件:行` 缺一不可
- **一次就够**:全绿就写结论收工;有 FAIL 或告警就定位、修改,再重跑,直到干净
- 例外两条:排查具体报错时可以只查该文件或该条告警;下游(仿真失败、综合报错)回头补查本环节时,
  目的是修问题,不是"补齐流程"
- 本检查**不构成关卡**:正在排查仿真问题时,不必停下补 lint

## 产物

写 `<模块根>/rtl/lint.md`(报告与 RTL 同目录:`rtl/` 既是源码目录,也放本环节的检查结论)。内容:

- **结论**:`PASS` / `FAIL` / `BLOCKED` / `NOT_APPLICABLE`
- 执行过的**命令原文**(可直接复现)
- 编译器报的 error / warning 逐条处理:改了哪里,或就地豁免的理由
- 逐条规范的核对结果;未通过项写清 `文件:行`
- `BLOCKED`:编译器未就绪(设置里标「未就绪」)→ 如实说明并停止,**不得声称已执行**
- `NOT_APPLICABLE`:`rtl/` 下无源码,或源码为 VHDL(本检查器仅覆盖 SystemVerilog / Verilog)

结论与证据均须可追溯。**未做本检查即进入仿真,等于把问题推到下游。**

## 出口:什么时候算写完

四条都满足才算本环节结束,否则如实标出缺哪条(不要写成"应该没问题"):

1. 与依据一致:端口照 `spec/spec.md`、路径照 `spec/flow.md`、参数照「参考资料」(第三步那三条)
2. `rtl-check` 跑过,且 `rtl/lint.md` 里的 `结论:` 不是 FAIL
3. 编译告警清零,或每条都有就地豁免的理由
4. 没做完的地方明确留在代码里(如某个子模块先留 `TODO`),并在结论里点出来

达标后把结论写进 `rtl/lint.md`,下一步交给仿真环节(测试平台用 `sim-new.mjs` 起)。
