# module-verif:验证(跑出数据 → 独立比对 → 判归属)

**验证 = 跑一遍 + 拿独立参照对一遍。** 测试平台只负责**把数据跑出来**,它证明不了数据是对的;
对不对由**独立参照(参考模型 / golden)**说了算 —— 不一致为零才算通过。

**判对错是 AI 自己的活**:仿真跑完先自己比对、自己确认;不一致时自己判断是 RTL、测试平台还是
参考模型的问题,改掉、重跑。**自己反复确认不了就停下来找用户协助确认** —— 不要放着一个不一致
往下走,也不要改判据把它绕过去。

## 前置

1. 找约定文件 `.fpga-workbench.json`(模块根);找不到则询问用户,见 `fpga-module-spec`
2. 读 `spec/spec.md`:接口、时钟、AC,以及验证方案 —— **比对输入路径、输出路径、格式**三项在其中;
   测试平台与参考模型都照着它写
3. **spec 里若做过 Python 原型**(`spec/explore/` 下,spec 的「参考资料」一节点名了它):
   它是参考模型 / golden 的首选来源(按算法写的,天然独立于 RTL)
4. spec 里三项都写 `none` → 本环节是 **NOT_APPLICABLE**,如实记下。**不得硬造一个比对**
5. **建议**先看 `rtl/lint.md` 是不是 PASS —— 但正在排查验证问题时不必停下补 lint

**没有测试平台 ≠ 本环节"不适用"**:若当前目标就是验证功能,则属 `UNVERIFIED` 或
`BLOCKED`(缺工具/缺平台),不是 `NOT_APPLICABLE`。通常答案是把测试平台写出来。

## 第一步:写测试平台(起文件靠命令,不手抄)

```
node "<自带命令目录>\verif-new.mjs" <模块根> <模块名> --template "<测试平台模板路径>"
```

默认落 `verif/tb_<snake>.sv`(`<snake>` 是模块名的下划线形式:`UartRx` → `tb_uart_rx`;
脚本只替模块名,与 `fpga-module-rtl` 同一条,要另换位置用 `--out`)。扩展名跟着模板走:
先在设置里选对**仿真语言**(SystemVerilog → `.sv` / Verilog → `.v` / VHDL → `.vhd`);
自带模板是 SystemVerilog 的,要写别的语言得自己准备对应语言的模板。

测试平台**必须有的三样**(写法自带 `tb.sv` 里都有,照它写即可;这里只讲判据):

- **失败必须留下可搜的标记**:判定用 `$fatal(1, ...)`,会打出 `** Fatal:` 那一行 ——
  **只 `$display` 一句 FAIL 是不行的**,脚本按行搜不到失败,这条是硬红线
  (ModelSim 下 `$fatal` **不会**让退出码非零,见「判据」;别的仿真器可能给非零退出,
  但**别只依赖退出码**)
- **判定要能自动做**:每处不符 `$error(...)` 并累计,别让"通过与否"靠人看波形
- **超时要有人管**:没有看门狗,挂死的仿真会一直挂着,无人察觉

结构化自检(握手成对、不出现 X、计数器不溢出、不死锁)写在测试平台里;**"数据对不对"不在这里判**
—— 那是下面的比对环节。

## 第二步:跑出来(全程命令行,不弹图形界面)

下面的例子按 **SystemVerilog**(`.sv`)写;选了 Verilog / VHDL 就把扩展名换成 `.v` / `.vhd`,
编译命令也换成对应语言的形式(`vcom` 对应 VHDL,`vlog`/`xvlog -sv` 对应 SV)。

**先用设置里选定的仿真器** —— 看会话开头「本机 FPGA 工具链」的**已就绪清单**:仿真器是
ModelSim / Vivado XSim / Verilator、路径是什么,都写在那里。**不得另行挑选一个。**

**ModelSim / Questa(默认)**

`run -all`、`quit -f` 这些是**仿真器自己的命令**,不是 shell 命令 —— 写成 `verif/run.do`
然后一次调用(会话开头给的调用姿势就是这个形态):

```
# verif/run.do
onerror {quit -code 1}
if {[file exists work]} { catch {vdel -lib work -all} }
vlib work
vcom -2008 <VHDL 文件...>              # 只有混语言模块才需要
vlog -sv ../rtl/<源码...> tb_<snake>.sv
vsim -c -voptargs="+acc=rn" tb_<模块名>
run -all
quit -f
```

```powershell
cd <模块根>/verif
& "<仿真器路径>" -c -do run.do
```

两处实测出来的坑,别省:

- **`vdel` 必须包在 `catch` 里(或先判 `work` 在不在)** —— 第一次跑没有 work 库时,
  裸的 `vdel` 会报错并**中止整个脚本**,后面全不执行,而退出码仍是 0:看起来"跑过了"其实什么都没跑
- **`$fatal` 之后 vsim 的退出码仍是 0**(2020.4 实测;`run -all` 既不抛错也不改退出码)。
  所以判成败**只能看日志**,别只看退出码 —— 详见「判据」

**Vivado XSim**(选了它就用 Vivado bin 目录下的这三个命令)

```
cd <模块根>/verif
xvlog -sv ../rtl/<源码...> tb_<snake>.sv
xelab -debug typical tb_<模块名> -s tb_sim
xsim tb_sim -runall
```

只写各仿真器**通用**的几条(具体工具的那些坑写在各选项自己的说明里,见会话开头的调用姿势):

- **编译顺序:被例化的在前**。文件多了按层级自底向上排;顺序错了编译会报未解析的模块
- 多个测试平台则**一个平台一个进程**跑(`tb_sub_*` → 其余 `tb_*` → `tb_top_*`),
  每个 `$finish` 结束一个进程

## 输出数据:格式是红线

比对数据写到 `spec` 里确认过的路径与格式,**不得自行改文件名或后缀**。

写十六进制要写**大写文本**:`$fwrite`/`$fdisplay` **不许用 `%x` / `%h`** —— 用 `%c` 加 ASCII 运算拼字符
(模板里有 `upnib` 函数)。原因很实际:比对按文本逐字节比,`%x` 的宽度与对齐不受控。

模型与文件的位置:**仿真模型**(厂商原语、行为级模型、加密模型)放 `verif/` 下,
用**真实的**那一份,不许拿简化版或快速桩顶上 —— 仿真用桩、综合用真 RTL,两边行为一旦不一致,
排查将十分耗时,且结论不可信。

## 第三步:看波形(用户要"看一眼"时)

**用户说要看波形,就必须真给他打开一条能看的路径** —— 批处理只留日志与数据文件,人工排查得靠
波形窗口。用自带命令:

```
node "<自带命令目录>\verif-wave.mjs" <模块根> --sim-path "<仿真器路径>"
```

它做四件事:编译 → 开 GUI → 把信号加进波形窗口 → **停在 0 时刻**(不自动 run,由人决定跑多长)。
生成 `verif/wave.do`;打开后敲 `run -all` 看全程、`run <时长>` 看一段,想换信号 `delete wave *` 再加。
先加 `--dry-run` 可以只看它要用哪些文件、哪个平台、哪个仿真器。

- 平台自己认(`verif/` 下按 `tb_top_` → `tb_` → `tb_sub_` 挑),要指定就 `--tb`
- 认不出仿真器时它会如实说,不会硬编一个命令;XSim 的 Tcl 不接受 `add wave`,要在波形窗口里手动加
- 需要**文本形态**的波形(写进报告、或给模型自己看)时,把工具自带的 `wlf2vcd` 转一下:
  `wlf2vcd -o verif/dump.vcd verif/vsim.wlf`,只保留需要的那一段再看
- 波形是**排查用的**,不是结论:看到的现象要落回 `verif/verif.md` 的结论与归属判断里

## 第四步:比对(拿独立参照,不是看波形)

1. 参考模型按**同一批输入**算出期望值
2. 与 DUT 输出逐词 / 逐字节比对
3. **不一致的位置全部列出**,不只报第一个
4. 有差异 → 先判归属,再动代码

### 参考模型必须独立(本环节唯一的硬要求)

- **不许** import RTL、仿真输出、生成的 IP,或任何实现细节
- 从 spec 描述的行为写起,不是从 RTL 抄起 —— 抄 RTL 的模型只能证明"它等于它自己"
- 跑之前先自查两条:模型**不得改写输入样本**;**不得把输入直接当输出返回**
- 宁可让比对**停住**,也不拿输入当期望、然后报"通过"

**参考模型通常就是 spec 里的 Python 原型**(spec 的「参考资料」一节点名了它):它按算法写、
天然独立于 RTL,正好符合上述几条。原型没做过 → 现按算法补一个,**不得照 RTL 的写法去凑**。

### 三种比对格式

| 格式 | 期望值谁出 | 用在 |
|---|---|---|
| `hex_words` | 整数词比对(逐拍 / 逐字) | 整数流 |
| `text_exact` / `binary_exact` | 参考模型给出期望字节 | 文本或二进制逐字节 |
| `custom` | 模块自己的比对器 | 上面都不合适 |

### 差异归属(最易出错之处)

- 差在**固定偏移或固定拍数** → 多为流水线延迟未对齐,不是逻辑错误
- 只差开头或结尾几拍 → 复位没放净、使能或首尾握手
- 整体差一倍、或位宽对不上 → 格式或符号位问题
- 模型改写了输入、或直接返回输入 → **独立性问题**,先修模型,其余不谈
- 全部一致但**样本数为 0** → 根本没比上,不得当作通过

归属判完再动代码:**RTL 错就改 RTL,测试平台错就改测试平台,模型错就改模型** —— 改完重跑。
两边不一致时,两边都可能错,**不得把"参考模型这么算"写成"RTL 是对的"**。

**一直确认不了就找用户**:同一处不一致反复出现、或判不出归属时,把事实摆出来请他协助确认
(哪两个文件、哪几拍、你怎么判断的)。不要放着不一致往下走,也不要改判据绕过它。

## 判据

**判成败靠日志与比对结果,不是退出码。** ModelSim 批处理下 `$fatal` 之后退出码仍是 0(实测),
所以"退出码 0 = 通过"是错的。

- **PASS**:测试平台跑出成功标记(模板里是 `ALL TESTS PASSED (err_cnt=0)`)、日志里没有
  `** Error:` / `** Fatal:` / `TB TIMEOUT`,**并且**独立比对:样本数 > 0、不一致数为 0
- **FAIL**:测试平台挂了(`** Error:` / `** Fatal:` / 超时,或没有成功标记),
  或比对存在不一致(给出数量与位置)
- **BLOCKED**:仿真器没就绪(设置里标「未就绪」)、参考模型没实现、输入文件缺失、输出文件没生成;
  也包括**退出码非零且日志里没有仿真结果**(Tcl 级错误:源文件打不开、编译失败、脚本写错)
- **UNVERIFIED**:`verif/` 下还没有测试平台(`tb_*`)—— 见「没有测试平台 ≠ 本环节不适用」
- **NOT_APPLICABLE**:spec 声明无文件比对,且这个模块**本来就没有可验证的行为**

挂死或超时时,先怀疑:时钟没起、复位没放、握手没接上、位宽对错。**不得第一反应就是调大看门狗。**

## 产物

写 `<模块根>/verif/verif.md`:

- 结论(`PASS` / `FAIL` / `BLOCKED` / `UNVERIFIED` / `NOT_APPLICABLE`)
- 跑过的**命令原文**(或该 `run.do` 的路径),可直接复制复现
- PASS 时:成功标记那一行原文
- FAIL 时:错误列表 + 日志路径 + **归属判断**(RTL / 测试平台 / 模型)+ 改了什么
- 输入 / 输出 / 格式(**照 spec**,改了就说清为什么)
- 样本数 + 不一致数与位置 + 参考模型版本;差异多时附一小段前后对比(头几个不一致的上下文)
- 覆盖了哪些 AC、哪些没覆盖(没覆盖就写"未覆盖",不得写"应该没问题")

测试平台源码(`tb_*` 与脚本)、参考模型与比对脚本、本次结果(日志、波形、输出数据)都放
`verif/`,按文件名区分;不要另建源码目录,也不要只把结果落在这里而把源码留在别处。

本环节只能证明"逻辑符合参照"。时序与上板不在本环节范围内。
