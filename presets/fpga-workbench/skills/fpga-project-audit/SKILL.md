# project-audit:工程体检

随时可跑,不占流程顺序,也**不自动挂在每个任务结尾**。目的是**找出会拖后腿的东西**:断链、
过时说明、重复文件、无法运行的脚本。

**审计只负责报告**:发现问题列出来,不得自行大规模重命名、移动或删除文件 —— 那些改动要经用户
确认后再单独做。

## 查六类

1. **文件与目录**:命名是否一致;是否存在重复文件、同功能多份、临时/备份/旧版本文件;
   是否有该被引用却找不到的文件;是否有无人引用的孤儿文件
2. **文档**:编码是否正常;文档名/标题/内容与实际状态是否一致;文档里提到的文件名、模块名、
   路径、脚本名是否**真的存在**;是否互相矛盾或过时
3. **引用闭环**:顺着 `工作流 → 文档 → 脚本 → 文件/目录` 走一遍,再看 `脚本 → 脚本`、
   `文档 → 文档` —— 重点找引用不存在的对象、旧名称、旧路径、断链
4. **脚本**:是否还在、路径对不对、引用的文件在不在、参数是否还是旧的;
   **能安全运行的做一次最小运行**,无法运行的写清原因
5. **工作流逻辑**:按 `输入 → 处理 → 输出 → 下游` 走一遍主流程,找断点、死流程、
   缺步骤、上下游不一致
6. **冗余与过时**:旧接口描述、旧路径、旧脚本、已经失效的检查规则

## 输出格式(固定)

```
[可疑过时文件]
[可疑过时文档]
[失效引用]
[失效脚本]
[需要运行验证的脚本]
[建议删除/归档内容]
[需要同步更新的描述]
[回归风险]
[最终状态：PASS / WARN / FAIL]
```

每个问题按 `[级别] 文件/位置 → 问题 → 影响 → 建议动作` 写,只报有价值的问题,不输出过程信息。

- **PASS**:没发现明显异常
- **WARN**:可继续工作,但建议尽快处理
- **FAIL**:会影响工作流继续运行,或会造成明显错误

## 铁律

- **不得自行大范围修改、移动、重命名或删除** —— 体检只"报"不"治"
- 不确定的标**"疑似"**,不得武断下结论
- 能验证的实际验证;**验证不了的明确标"未验证"**
- 不得因为上次检查通过就默认现在没问题(也不得只看最近改过的文件)

## 产物

写 `<工作区根>/project/audit/audit.md`:上面那个固定块 + 逐条明细。
用户要"清理"时,按明细一条条确认后再动,不得一次性批量处理。
