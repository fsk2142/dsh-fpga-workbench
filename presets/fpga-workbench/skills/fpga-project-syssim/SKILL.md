# project-syssim:系统级仿真

## 做与不做的判断

**按风险判断,不按模块个数**。值得做的信号:模块之间有握手或背压、跨时钟域的数据流、接口协议
容易出错、或者上板代价高(要拆机、要外设)。单个模块自己就能测清楚、集成只是把单向数据连起来
—— 那就记 `NOT_APPLICABLE`,不得为了走流程造一个没用的顶层测试平台。

**判断随时可以改**:一开始没打算做,后来发现接口复杂了就补上,比一直不做强;也不必在
`project/spec/spec.md` 里一次把它定死。

这条判断要在 `project/spec/spec.md` 里就定下来,不要做到一半才想起来。

## 和模块级仿真的区别

模块级(`fpga-module-sim`)验的是"这个模块对不对";这里验的是"**互联之后是否仍然正确**" ——
重点在接口:握手会不会卡、背压会不会丢、跨时钟域的数据会不会错位、复位释放顺序对不对。

**模块级的测试平台不得当作顶层测试平台使用**,它们的检查目标不一样。

## 怎么做

1. 顶层测试平台放在工程的仿真目录下,**照测试平台模板写**(模板路径见会话开头那段)
2. 激励:优先用**真实的一段数据**(工程里已有的数据文件),比随机数更能暴露问题
3. 检查:数据比对 + 握手断言。数据比对建议直接**接模块级的参考模型**(`verif` 那一环节的),
   不要另写一套 —— 独立模型写两遍必然分叉
4. 跑法同模块级:`vsim -c`,全程命令行,不许弹界面

## 判据

- **PASS**:顶层测试平台跑完,数据比对一致,没有握手卡死与超时
- **FAIL**:数据不一致、或握手卡死、或断言触发
- **BLOCKED**:缺数据文件 / 缺顶层测试平台 / 仿真工具没就绪
- **NOT_APPLICABLE**:按上面那条判断,这个工程不做系统级仿真

## 产物

写 `<工作区根>/project/syssim/syssim.md`:结论 + 命令原文 + 激励数据来源 +
比对方式与结果 + 覆盖了哪些跨模块路径、哪些**没覆盖**。

系统仿真失败时,先排查接口(位宽/握手/时钟域),而非某个模块的内部逻辑 ——
模块级已经各自验过了。
