# module-rtl:编写、编译检查与规范核对

**写完 RTL 再统一检查。** 逐文件运行效率低:一次跑全量、报错集中定位与修改,结论写进 `rtl/lint.md`。

- 排查具体报错时,可只查该文件或该条告警
- 下游出问题(仿真失败、综合报错)时可回头补查本环节,目的是修问题,不是为了"补齐流程"
- 本检查**不构成关卡**:正在排查仿真问题时,不必停下补 lint

## 前置

1. 找约定文件 `.fpga-workbench.json`(模块根;找不到则询问用户,见 `fpga-module-spec`)
2. 读 `spec/spec.md`:接口、判据、器件 —— 规范检查的例外也按它判
3. 待查源码按设置里选定的 RTL 语言取:`rtl/` 下的 `.sv` / `.v`(递归)。
   源码为 VHDL 时本检查器不覆盖 → 结论记 `NOT_APPLICABLE` 并说明原因,**不得视为通过**

## 第一步:用模板生成文件,再编写逻辑

**不要从空文件写起。** 模板就是本模块的格式规范:文件头、九个小节块、说明块、对齐都由它给出,
照它起文件能省掉整类返工。

- 模板取设置里配好的那份(见会话开头「本机 FPGA 工具链」的模板一节;留空即插件自带那套);
  动手前先读它
- 文件名 = 模块名 + 按设置里选定 RTL 语言的扩展名(`.sv` / `.v`)
- 先落地模板骨架,再往里填逻辑:文件头字段逐个填实(名称、日期、版本、作者、功能说明),
  九个小节块按模板保留,断言连 Purpose / Trigger / Failure 一并写
- 模板里已经写好的不要再另立一套:`` `resetall `` / `` `timescale `` / `` `default_nettype none ``、
  `end else begin` 同行、端口名与类型对齐至第 69 列
- 设置里没有对应语言的模板时(自带模板是 SystemVerilog 的),照它的**结构**写一份对应语言的骨架;
  不要因为模板语言不同就丢掉这套结构

## 第二步:编译器检查

**用设置中选定的编译器。** 会话开头「本机 FPGA 工具链」已写明是哪个工具、路径是什么,并给出该工具
的调用姿势 —— 按那个姿势执行,下文以 Verilator 为例:

```powershell
& "<编译器路径>" --lint-only -Wall --top-module <顶层模块名> <文件...>
```

- 只查 `rtl/` 下的源码(递归);`sim/` 下的仿真模型不参与本检查
- 报 `module not found`、而该模块来自 IP(只有 `.xci` 或加密模型,没有可检查的 HDL)属正常现象:
  把该 IP 的端口 wrapper 一并传入,或临时生成只含端口的黑盒 stub 加入命令行。
  **不得为通过检查而改动端口**
- 告警须清零;确需压制时在源码内**就地豁免**(`/* verilator lint_off XXX */` …
  `/* verilator lint_on XXX */`)并注明原因。**禁止用 `-Wno-XXX` 全局屏蔽**

## 第三步:逐条核对规范

**格式以模板为准**:RTL / 测试平台 / 约束各有模板(见会话开头「本机 FPGA 工具链」的模板一节;
未提供即插件自带那份),核对前先读模板。

**机械部分先跑自带命令**(路径见会话开头「本模式自带的命令」):

```powershell
node "<自带命令目录>\check-rtl.mjs" <模块目录>
```

覆盖文件头、九个小节块、端口类型、复位极性、always_ff、end/else、断言、制表符、行尾、代码行非英文、
测试平台自检,并给出**行号**。退出码 0 = 无阻塞项(可能仍有警告)/ 1 = 有阻塞项 / 2 = 用法或环境问题。

工具判不了的须自行读代码:一个 always 块内混放不相关信号、断言是否正确、命名与结构。

核对结果对照下面两类规则;书写时就按它们来,本环节只做写后核对。

**格式类(机械可判)**

- 禁用制表符
- 代码行限英文(注释除外)
- 行尾统一,单个文件内不得混用

**结构类(须读代码判定)**

- **文件头 11 行**字段齐全:File Name / Module Name / Created Date / Updated Date / Version /
  Author / Copyright / Open Source(专有声明),其后 2–5 行模块功能说明(数据流、输出格式)
- 开头 `` `resetall `` + `` `timescale `` + `` `default_nettype none ``,结尾收回 nettype
- 端口类型仅限 `input wire` / `output logic` / `inout tri`;端口名与类型**对齐至第 69 列**
- `end else begin` 同行书写
- `always_ff` 仅用 `posedge`
- 复位高有效
- **九个小节块齐全且顺序不变**:Local Parameters / Types / Registers / Combinational Logic /
  Sequential Logic / Functions Module / Task Module / Module Instantiation / Assertions
- 每个 RTL 须有设计断言,并写明 Purpose / Trigger / Failure
- **一个 always 块内不混放不相关信号** —— 除非共用同一套控制逻辑(同一状态机、同一事务生命周期、
  同一寄存器组)。无法说明其共同控制关系时拆分
- 测试平台须含 `$fatal` / `$error`:仿真失败须能被自动捕获,不得依赖人工观察波形

**外来代码另行判断**:厂商 IP、他人提供的模块放在 `rtl/ip/` 下 —— 机械检查**跳过该目录**
(它们不按本模块的格式规范书写)。这类代码的报错先与用户确认是否要改,**不得擅自重排厂商代码**。

## 产物

写 `<模块根>/rtl/lint.md`(报告与 RTL 同目录:`rtl/` 既是源码目录,也放本环节的检查结论;
`stage-status` 按此位置读结论)。内容:

- **结论**:`PASS` / `FAIL` / `BLOCKED` / `NOT_APPLICABLE`
- 执行过的**命令原文**(可直接复现)
- 编译器报的 error / warning 逐条处理:改了哪里,或就地豁免的理由
- 逐条规范的核对结果;未通过项写清 `文件:行`
- `BLOCKED`:编译器未就绪(设置里标「未就绪」)→ 如实说明并停止,**不得声称已执行**
- `NOT_APPLICABLE`:`rtl/` 下无源码,或源码为 VHDL(本检查器仅覆盖 SystemVerilog / Verilog)

结论与证据均须可追溯。**未做本检查即进入仿真,等于把问题推到下游。**
