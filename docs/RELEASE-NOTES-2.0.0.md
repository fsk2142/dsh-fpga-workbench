## 这一版做了什么

主线是一句话：**把「检查没发生」从「通过」里剥出去。**

三轮外部审查共约 40 项发现，全部处理。原来的问题集中在「事实如何变成结论」——
几处程序把「没拿到完整事实」「只验证了一个子集」进一步解释成「通过」。

| 位置 | 原来的假绿 |
|---|---|
| Verilator lint | 可执行缺失 / 超时 / `status=127` / 其它非零退出 |
| 引脚审计 | 缺 `PACKAGE_PIN`、期望表有解析不了的约束 |
| 时序报告 | 非法数字被 `NaN→null` 当成合法 `NA`；数字行缺列被截断 |
| 覆盖率 | 门槛类别缺失时退回参考类别判达标 |
| AC 追溯 | 全部标「不适用」冒充完成验证 |
| bitstream | 已完成的旧 bit 跳过刷新检查；属性读不到仍归档成功 |

现在这些情况分别报 `BLOCKED` / `UNVERIFIED` / 退 3，并说明**为什么判不了**。

## ⚠️ 不兼容变更

### 1. `provenance` 语义收紧

旧的 `--begin` / `--end` 两阶段**不跑 Vivado 也会写 `verified`** ——
那个标记证明不了构建发生过。现在：

| 原值 | 现在 |
|---|---|
| 两阶段写出 `verified` | 写 `input-snapshot-matched`（只说明前后输入摘要一致） |
| 磁盘上已有的 `verified` | 读取时降级为 `legacy-unverified` |

**本版本没有任何路径能产出「来源已验证」。** 那需要受控构建调用记录
（run / 工具返回状态 / 产物身份），当前未实现。

JSON 消费方注意：新增 `recordedProvenance`（记录原值）与 `downgraded`，
旧的 `provenance` 字段含义已变。

### 2. manifest schema 1 → 2

旧清单仍可读（能比哈希），但来源状态按上面降级。

### 3. 退出码细分

| 码 | 含义 |
|---|---|
| 0 | 通过 |
| 1 | 真实不符 |
| 2 | 输入/用法错误 |
| **3** | **证据不足（UNVERIFIED / NOT_APPLICABLE）** |

只判 `!== 0` 的脚本不受影响；区分 1 与 3 的请对照各工具说明。

## 其它修复

**准确性**

- 端口名大小写：`LED` 与 `led` 不再被当成同一端口
- 跨 XDC 文件属性合并：引脚与电平拆文件写不再误报「缺少电平标准」；
  同字段多值报「属性冲突」而不是猜生效顺序
- 同一端口重复赋同值：不再误报「两个端口抢同一 pin」
- 源摘要补上 `.mem` `.coe` `.mif` `.hex` `.dat` `.bd` 等初始化数据与 IP 描述
- 报告选版：多份 routed 按 mtime 取最新并披露被放弃的候选；
  阶段判断只看 basename（父目录名不再干扰）

**失败路径与恢复**

- `--write` 默认不覆盖已有 manifest（那会掩盖「源码与 bit 对不上」）
- 多份 manifest 要求 `--top` 显式指定，不静默取第一份
- `--part` 校验时真比对（原来接受但不比对）
- `--end` 绑定 `--begin` 的 top/part，旧 intent 不能无限重用冒充新构建
- MCP 状态一致性收到一处：`pendingDispose` 未清时不再报「已连接」

**健壮性**

- **bitstream 模板不再依赖 `clock` 命令** —— 精简 `tclsh86t`（Vivado 自带）
  没有它，旧 ltx 存在时会让整份脚本崩在归档阶段
- 旧 ltx 改名失败现在**退非零**（上一版只 WARN 就报成功，
  磁盘上会留下新旧混合的现役集合）
- coverage 文本输出不再因 `gate=null` 崩溃
- `check-fpga-tools` 修掉用例间环境变量残留与祖先目录名干扰

## 测试

断言数 **1965 → 1988**。新增持久回归覆盖：缺 pin、同端口重复赋同值、
期望未解析、时序缺列、父目录名干扰、旧 `verified` 降级、两阶段语义、
`--end` 身份绑定。

```

build        2/2
pnpm test    源码 20 项 + 宿主 3 项 · 1988 条断言全绿
```

  被解释为「已是最新」。若市场用这个组合表示「查不到」，会误报。
  未改代码 —— 需要先读市场 API 契约
