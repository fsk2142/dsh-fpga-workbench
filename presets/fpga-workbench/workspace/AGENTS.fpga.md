**这是 FPGA 开发模式的工作区规则**,按项目改这一份即可。它只管本模式下的做法,不改变
`spec/` `rtl/` `verif/` `synth/` 里那些产物格式与流程本身(那些见技能与模板)。

**这几条动手规则只在这里维护(唯一出处)**:会话提示(Persona)与各技能只引用本区块、不重复
一套自己的版本 —— 改口径改这里,免得「人设放宽了、技能还强制」。骨架(`setup-scaffold.mjs`)
会把这份文件原样复制为 `<根>/AGENTS.fpga.md`;项目里还没有那份文件时,按各技能自己那条判据办。

1. **动手前先看清现状**:工作区里有什么、相关报告与已有证据是什么。已有报告按需读,先看与当前
   问题直接相关的那几份;不要凭印象假设。
2. **方案要不要先画图确认,按任务风险判**(不是按"是否新增功能"):
   - **先出图确认**:重大架构、公共接口、跨时钟方案、关键数据通路,以及用户可见的算法决策 ——
     这些**尚未确定**时,先把实现思路画成流程图(模块级)或框图(工程级)给人确认再动 RTL
   - **局部修复直接动手**:改语法错、单条 lint 或编译告警、已有模块的局部 Bug,以及已有批准方案里
     的普通实现 —— 只要求读相关代码与项目约束、改完做聚焦验证;**不要求**先补一整套规格,也不要求
     先建 `spec/flow.md`
   - 图没确认 = 方案没确认;中途发现图走不通,先说清怎么改、改完图再继续,不要默默换一条路
3. **缺规格文件 ≠ 缺关键决策依据**:没有 `spec/` 或 `flow.md` 不必然阻塞局部任务(读相关代码与
   项目约定即可);只有**影响结果**的关键决策(接口、时序口径、复位极性与事件沿、算法参数)
   确实定不下来时,才回去问用户 —— 缺文件本身不是问的理由。
4. **确定性检查交给脚本**:能用命令判定的就别用肉眼替代,把命令输出当事实依据。
5. **局部问题走局部闭环**:定位 → 最小必要修改 → 相关验证;失败就继续定位,不要当成"这一步
   结束"往下走。小改动优先局部验证,不必每次重跑全链。
6. **分清"任务完成"与"正式验收"**:前者按当前范围与实际验证结果说;后者要求与交付范围相称的
   证据。工具缺失时可以继续分析并给出未验证的修复,但要写明未验证,不得说成已通过。
7. **不硬造记录**:只在真跑了那个环节、或正式交付/明确要求留档时才写结论文件;短诊断在回复里
   说清做了什么、哪些没验证即可。
8. **高风险操作先取得确认**:改管脚/电平/时钟例外/固化参数、把 bit 下到板子、擦除或清空、不可逆
   的批量改动 —— 先核实目标与依据,并让人点头,不要自行推断参数。第三方工具自管的可再生物
   (如 `verif/work`)由工具自己清理;**用户的源码与产物不得由代理主动永久删除**;清库 / 擦除前
   必须先取得确认。
9. **复位与事件沿以实际工程为准**:模板默认可以用高有效复位(以及模板指定的时序风格),
   **已有工程按它实际的接口与项目约定来**;要改复位极性或事件沿,必须先说明理由并取得确认。
10. **长任务的结论与证据落到文件里**:模块级写模块自己的环节目录,工程级统一写工程根的 `doc/`;会话会被
    压缩,文件不会。结果文件保留 `结论:` 那一行;判定词(`PASS`/`FAIL`/`BLOCKED`/`UNVERIFIED`/
    `NOT_APPLICABLE`)的含意见验证技能 `fpga-module-verif` 的那张状态表(唯一权威)。
11. **机器级设置不写进工程脚本**:Vivado 的 `general.maxThreads`(以及自定义板卡的
    `board.repoPaths`)放机器级 `<Vivado>/scripts/Vivado_init.tcl` 或用户级
    `~/.Xilinx/Vivado/Vivado_init.tcl`,它在每个 Vivado 进程(含 `launch_runs` 另起的 run 进程)
    启动时生效;ModelSim / Questa 的默认值放 `modelsim.ini`(改了会自动要求重编,编译身份里记着它)。
    `launch_runs -jobs` 管的是并行 run,不是单个 run 的算法线程 —— 这两件事都别在工程 Tcl 里再设一遍:
    launcher 脚本里设的 `set_param` 传不到 run 进程,只会让人误以为生效了。
12. **交给 Tcl 的 Windows 路径先归一化**:Vivado / ModelSim 的 Tcl 里 `\f` `\v` `\t` `\r` `\b` `\n` 都是
    转义 —— 路径一旦进**双引号字符串**就会被吃掉(实测 `C:\Work\fpga_module\verif` 会变成
    `C:Work<0x0C>pga_module<0x0B>erif`)。做法:一律写 `/`、或用 `{...}` 花括号、或在拼接**之前**
    `[string map {\\ /} $path]` —— 已经转义坏掉的字符串再归一化救不回来。典型翻车点:把环境变量
    (如 `APPDATA`)手工拼进 `.tcl`。
13. **是环境问题还是设计问题,先按这条排查**:① 受限沙箱下 `launch_runs` 起的 run 子进程会**挂死**
    (`ISEWrap.js` 经 WSH `Exec` 要命名管道;被挡后 `runme.log` 停在 banner、`wait_on_run` 无限等)
    —— 要么给足文件权限,要么接受"单进程非工程流"的损失(后者没有 `impl_1` run state,bitstream
    环节会因为找不到 `<TOP>_routed.dcp` 而拒绝);② Vivado 写不了 `%APPDATA%\Xilinx`、报
    `[Common 17-354]` / `tclapp::load_apps failed` 时,正解是 `XILINX_LOCAL_USER_DATA=NO`
    (AMD AR 62945,让 TclStore 从安装目录读),**不要**靠重定向 `APPDATA` —— 那正是第 12 条那个坑的
    来源;③ MSYS2 装的 Verilator 必须带 `VERILATOR_ROOT=<msys2>/mingw64/share/verilator`
    (会话提示的"已就绪工具"里会给推导值),否则第一步就报 `Cannot find verilated_std_waiver.vlt`。
